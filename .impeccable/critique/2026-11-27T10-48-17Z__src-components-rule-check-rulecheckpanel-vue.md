# 规范校验面板（v2）critique

目标：src/components/rule-check/RuleCheckPanel.vue + RuleCheckViolationRow.vue（cursor/rule-check-panel-v2-6f6f，d2b6d20d）
模式：Operate（审查几百条检出的工具面板），停靠栏宽约 350 px。

## 设计特异性

- 评审：内容与交互是这个产品特有的（构件对、实测 / 阈值 / 差、分引擎进度、精算漏斗）；视觉语言是通用的 Tailwind 灰阶 + 小芯片。Operate 模式下克制是对的，但层次靠大量小字和边框而不是空间与字重。
- 检测器（源码扫描）：两个组件 0 处。
- 检测器（页面叠加）：整页 71 处，面板内 69 处——约 55 处 10 px 功能文字（低于 11 px）、约 10 处对比度不足、几处 11 px 正文。另 2 处是整个应用的（顶栏橙底白字、Roboto 字体占比），不在本面板范围。检测器印证了评审里「小字偏多」，并把它从 P2 提到 P1：最关键的「实测 / 阈值 / 差」一行全是 10 px。

## 总体印象

功能齐、流程对，但结果页的「主角」——违规列表——被上方的概览和横幅挤到只剩三行，而每行里最要紧的数字又是整块里最小的字。最大的机会：让列表和「差多少」成为画面中心。

## 做得好的

- 每条违规三行式（规则 / 构件对 / 实测、阈值、差）把审查要看的信息按顺序摆好，「差 47.9」右对齐一眼可扫。
- 异常写成人话并带下一步：「属性/火灾分区 没有跑完 · gen-model 服务出错（HTTP 503）；其余 3 个引擎照常」+ 重试，原始报错收进「技术细节」。
- 运行设置跑完自动收成一行摘要，是真正的渐进展示。

## 主要问题

1. **[P1] 结果区顶部堆叠，列表只剩 3 行**
   - 为什么：失败横幅 + 提示 + 概览（统计格、比例条、精算漏斗、全项目 BRAN、截断提示、两行引擎标签）+ 工具条合计约 480 px，900 px 的停靠栏里审查者每次只看到 3 条。v2 省下的设置空间又被概览吃回去了。
   - 怎么改：概览和横幅放进滚动区、跟列表一起滚走，只留搜索筛选工具条吸顶；引擎标签并进「本次结果」那一行（只在有失败时展开）；截断提示压成一行。
   - 建议命令：/impeccable layout（+ distill）
2. **[P1] 关键数字太小、对比度不足**
   - 为什么：「实测 / 阈值 / 差」、统计格标签、徽标、CSV / JSON / 清空 / 重试都是 10 px；红字 #ef4444 在白底 3.8:1、零值 2.0:1、失败横幅红字 3.0–3.3:1，都不过 AA。审查者要连续读几百个数字。
   - 怎么改：数据和可点文字至少 11 px，「差」字重加大做行内主角；红色改用更深的 red-700（白底 ≥ 4.5:1），零值用 muted-foreground；横幅正文用 foreground、只保留标题红色。
   - 建议命令：/impeccable typeset + /impeccable audit
3. **[P2] 统计格口径重叠，数字对不上**
   - 为什么：火灾分区的检出也算在「违规」里，四格看起来能相加，实际违规 8 + 火灾 1 ≠ 总数 8。
   - 怎么改：火灾分区不再做并列的格，改成「其中火灾分区 1」小字，或从「违规」里扣掉，让格子之和 = 标签页上的总数。
   - 建议命令：/impeccable clarify
4. **[P2] 「清空」易误点、没有撤销**
   - 为什么：10 px 的「清空」紧挨 JSON 导出，点错就丢掉一次几分钟的全项目运行结果。
   - 怎么改：换成二次确认（点一下变「再点一次清空」，3 秒后复原）并与导出拉开距离。
   - 建议命令：/impeccable harden
5. **[P2] 重复的重试入口，目录结果「✕ N」有歧义**
   - 为什么：同一个失败引擎在横幅和引擎标签里各有一个「重试」；目录里「✕ 532」的 ✕ 像「删除」。
   - 怎么改：只保留横幅里的重试，引擎标签只展示状态；目录结果改成「532 项」加红点。
   - 建议命令：/impeccable polish

## 角色试用

- **Alex（审查几百条的老手）**：↑↓ 要先点一下列表才生效；一屏只有 3 条；「差 47.9」和「实测」都是 10 px，扫不快。
- **Jordan（第一次用的设计人）**：「分级」「精算 / 估算」「Copy-of」「选集」「BRAN 未填」没有就地说明；不知道统计格能点。
- **Sam（低视力 / 读屏）**：10 px 文字和 3:1 的红字；普通违规的严重度只靠左侧色条；违规行是可点的 div，没有角色与展开状态给读屏。

## 小问题

- 行内比例条红色、长度 = 实测 / 阈值：越长反而越接近合格，语义反了；应该让红色表示「差的那一截」。
- 统计格能点但不像按钮。
- 目录分组后每行还重复引擎标签。
- 三维着色「分级」意思不明，可改「按严重度」。

## 值得想的问题

- 如果「差多少」是每条违规的主角，它是不是该是行里最大的字？
- 一次顺利的运行之后，审查者还需要看四个引擎的用时吗？
- 概览看一眼就够，它是不是应该一滚动就让位给列表？
