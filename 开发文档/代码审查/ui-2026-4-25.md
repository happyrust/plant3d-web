# 校审核批注 UI 操作修复方案

## Summary

修复目标：让批注处理入口、详情打开、再次提交、回复区按钮和高风险状态动作都符合用户预期，避免“点了没反应、点 A 进 B、没处理完也能提交”的问题。

优先级：

1. 先修表格打开详情和筛选错位。
2. 再修设计侧再次提交前的批注检查。
3. 最后清理假按钮，并给高风险动作加保护。

## Key Changes

### 1. 批注表格右键打开详情

涉及：`AnnotationTableView.vue`、设计侧和审核侧父组件。

- 右键菜单“打开处理详情”改为触发 `open-annotation`，不再只触发选中。
- 菜单文案去掉 `drawer`，统一为“打开处理详情”。
- 设计侧行为：进入批注详情页。
- 审核侧行为：切回卡片列表并定位到该批注，因为审核侧当前没有单独详情页。

验收标准：

- 表格行双击和右键“打开处理详情”行为一致。
- 设计侧能进入详情页。
- 审核侧能切回可处理面板并定位批注。

### 2. 表格打开详情时清理卡片筛选影响

涉及：`DesignerCommentHandlingPanel.vue`、`ReviewPanel.vue`。

- 从表格打开详情或打开处理面板时，先把批注筛选重置为 `all`。
- 详情选中目标必须来自当前 `formId` 范围内的完整批注列表，不能被“待处理 / 已修改 / 已驳回 / 高优”筛选挡掉。
- 保持表格自身搜索、状态筛选、严重度筛选不变。

验收标准：

- 卡片列表处于“待处理”筛选时，表格里双击一条“已修改”批注，仍能进入该批注详情。
- 不出现空详情。
- 不自动跳到另一条批注。

### 3. 设计侧再次提交前增加批注检查

涉及：`DesignerCommentHandlingPanel.vue`，复用现有 `reviewAnnotationCheck` / `runReviewSubmitPreflight`。

- 点击“处理完成后再次提交”前执行检查：
  - 还有未保存数据：提示“请先确认当前数据，再执行流转”。
  - 还有未处理批注：提示检查接口返回的信息。
  - 检查通过后再调用 `submitTaskToNextNode`。
- 检查参数沿用审核侧规则：
  - `taskId`
  - `formId`
  - `currentNode`
  - `intent: 'submit_next'`
  - `includedTypes: ['text', 'cloud', 'rect']`
- `obb` 仍按当前规则不作为提交阻塞项，避免扩大改动范围。

验收标准：

- 未保存批注或测量时，按钮不可直接提交。
- 批注检查失败时，不提交任务，并显示失败原因。
- 批注检查通过时，正常再次提交。

### 4. 回复区附件和截图按钮先隐藏

涉及：`ReviewCommentsTimeline.vue`。

- 暂时移除或隐藏回复区的附件按钮和截图按钮。
- 不新增上传接口、不新增截图流程。
- 保留文字回复能力。

原因：

- 当前按钮没有任何动作，属于误导性入口。
- 附件和截图能力应单独做完整设计，不混入本次修复。

验收标准：

- 回复区不再显示不可用的附件/截图按钮。
- 发送文字回复不受影响。

### 5. 高风险批注动作加保护

涉及：`ReviewCommentsTimeline.vue`。

- “已修改”：保留一键操作。
- “同意”：保留一键操作。
- “不需解决”：要求填写处理说明，否则提示“请填写不需解决原因”。
- “驳回”：要求填写驳回说明，否则提示“请填写驳回原因”。
- 不新增弹窗，保持界面轻量。

验收标准：

- 空备注点击“不需解决”不会改变状态。
- 空备注点击“驳回”不会改变状态。
- 填写说明后动作正常记录到时间线。
- “已修改 / 同意”不增加额外阻塞。

## Assumptions

- 本次只修 UI 操作问题，不新增后端接口。
- 不改批注数据结构。
- 不新增附件上传或截图能力。
- 设计侧驳回后的主路径仍是“处理批注 → 确认当前数据 → 再次提交”。
- 审核侧没有独立详情页，所以“打开处理详情”表现为切回卡片处理面板并定位批注。
