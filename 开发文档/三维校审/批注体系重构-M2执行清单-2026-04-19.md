## 1. 阶段目标

让"平台内任务恢复 / workflow-sync 嵌入恢复 / 离线导入"三类入口都先经由 **`ReviewSnapshot`** 中间结构再转 viewer payload，做到：

1. 中间结构语义统一，UI 层"理论上"可以只消费 snapshot；
2. SHADOW 阶段下与现行 payload 字节级一致，不影响线上行为；
3. 为 M3（评论解耦）/ M4（后端 metadata 扩展）/ M7（双层渲染）提供稳定锚点。

非目标：

- 本阶段不修改 `useToolStore` 的真源结构；
- 本阶段不动 `ReviewCommentsTimeline`、`ReviewPanel.vue` 等 UI；
- 本阶段不引入 `annotationKey` 真正消费，仅在 snapshot.meta 里允许后续填入。

## 3. ReviewSnapshot 字段约定（M2 版）

仅落地以下字段，其余预留位允许 `undefined`：

```ts
type SnapshotSource = 'task_records' | 'workflow_sync' | 'import_package';

interface SnapshotAnnotation {
  annotationId: string;
  annotationType: 'text' | 'cloud' | 'rect' | 'obb';
  taskId?: string;
  formId?: string;
  workflowNode?: 'sj' | 'jd' | 'sh' | 'pz';
  reviewRound?: number;
  annotationKey?: string;
  payload: Record<string, unknown>;
}

interface SnapshotComment {
  commentId: string;
  annotationId: string;
  annotationType: 'text' | 'cloud' | 'rect' | 'obb';
  authorId?: string;
  authorName?: string;
  authorRole?: string;
  content: string;
  replyToId?: string;
  createdAt: number;
  annotationKey?: string;
  taskId?: string;
  formId?: string;
  workflowNode?: string;
  reviewRound?: number;
}

interface SnapshotMeasurement {
  measurementId: string;
  kind: 'distance' | 'angle' | 'unknown';
  payload: Record<string, unknown>;
}

interface ReviewSnapshot {
  source: SnapshotSource;
  taskId?: string;
  formId?: string;
  workflowNode?: string;
  taskStatus?: string;
  annotations: SnapshotAnnotation[];
  comments: SnapshotComment[];
  measurements: SnapshotMeasurement[];
  attachments: ReviewAttachment[];
  models: string[];
  meta: {
    sourceVersion: number;
    createdAt: number;
    /** 评论尚未走独立真源时使用：`${annotationType}:${annotationId}` */
    inlineCommentIndex?: ReadonlyArray<string>;
  };
}
```

## 5. SHADOW 退出条件（进 CUTOVER 之前）

- 在两个 restore 入口都接入 SHADOW；
- 自测 + 浏览器恢复一次平台任务 + 一次嵌入恢复，diff 告警为 0；
- 性能基线（补遗 §6）首次任务 100 批注 < 500ms 不退化（与现状对比 ±5%）。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| `inlineCommentIndex` 与 `attachCommentsToItems` 顺序不一致导致 payload 字节不同 | adapter 内严格保留输入顺序，单测以现有 `buildReviewRecordReplayPayload` 为黄金对照 |
| `WorkflowRecordData` 与 `ConfirmedRecord` 的 `measurements` 字段类型不同 | snapshot 内 `payload: Record<string, unknown>`，由 toolStoreAdapter 还原回旧 payload；adapter 不强制规整字段 |
| 后端尚未提供 `annotationKey` / `workflowNode` / `reviewRound` | snapshot 字段允许 `undefined`，前端不在 M2 里依赖 |
| SHADOW diff 噪声大 | 仅在 `localStorage['review.flag.REVIEW_B_SNAPSHOT_LAYER_SHADOW']='1'` 时启用；默认彻底关闭 |

## 7. 后续衔接

- M3 评论解耦时，`SnapshotComment[]` 直接成为 thread store 的初始化数据源；

- M7 双层渲染时，snapshot 内 `annotations` 自然属于 confirmed layer，draft layer 由 `useToolStore` 当前状态投影。
