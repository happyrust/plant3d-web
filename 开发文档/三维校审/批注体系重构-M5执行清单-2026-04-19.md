## 0. 准入条件

- [ ] M3-T8 CUTOVER 在生产稳定 ≥ 1 周
- [ ] M4-T1 ~ M4-T5 后端字段已发布（含 WebSocket 事件体含 `annotationKey/taskId/reviewRound`）
- [ ] 当前 `useReviewStore.onCommentAdded` 仅作为外部回调入口，未真正写 store

## 1. 阶段目标

1. 引入 **`commentSyncService`**：单一 owner，订阅 `useReviewStore` 的 WebSocket 事件流；
2. 实时事件按 `(annotationKey, commentId)` 幂等去重，按序列号 / `createdAt` 排序后写入 `commentThreadStore.upsertComment` / `deleteComment`；
3. 提供 HTTP fallback：当 WebSocket 断开 > 阈值时切换为 polling，完全不依赖事件；
4. 重连后做 **convergence pull**：以 task 维度拉一次全量评论 → `mergeComments` 收敛；
5. 与 M3 / M4 闭环：评论与 record 的更新延迟 < 300ms（补遗 §6）。

非目标：

- 本阶段不动 record / task 事件路径（仍 trigger reload）；
- 本阶段不引入 SSE / 长连接以外的传输；
- 本阶段不做"已读 / @人 / 分页"等高级评论能力（M7 之后）。

## 2. 现状（盘点）

### `plant3d-web/src/composables/useReviewStore.ts`

```ts
// L362-372
type CommentAddedCallback = (data: unknown) => void;
const commentAddedCallbacks: CommentAddedCallback[] = [];

function onCommentAdded(callback: CommentAddedCallback) { ... }

// L474-481
case 'comment_added': {
  console.log('[ReviewStore] New comment:', message.data);
  for (const cb of commentAddedCallbacks) {
    try { cb(message.data); } catch { /* ignore */ }
  }
  break;
}
```

问题：

- 回调直接派发 `message.data`，没有 schema 校验、没有去重、没有顺序保证；
- 没有任何组件实际注册 `onCommentAdded`（前端搜索 0 命中），即评论实时更新依赖手动刷新；
- 重连后没有 catch-up；
- HTTP fallback 不存在。

### `plant-model-gen` WebSocket 事件体（M4-T5 后）

```json
{
  "type": "comment_added",
  "timestamp": "...",
  "data": {
    "comment": {
      "id": "...", "annotationId": "...", "annotationType": "...",
      "annotationKey": "...", "taskId": "...", "workflowNode": "sj",
      "reviewRound": 2,
      "authorId": "...", "authorName": "...", "authorRole": "sh",
      "content": "...", "replyToId": "..."?,
      "createdAt": 1700000000000
    },
    "seq": 12345          // 服务端单调序列号（M5 要求后端补）
  }
}
```

## 3. 字段约定

| 字段 | 用途 |
| --- | --- |
| `comment.id` | 主键，去重第一道 |
| `comment.annotationKey` | thread bucket 选择 |
| `seq` | 单调序列号；service 内做 `seq <= lastSeen` 即丢弃 |
| `timestamp` | 客户端展示用；不参与去重 |

## 5. 任务列表

### M5-T1 transport 抽象

- [ ] `commentSyncTransport.ts`：`createWebSocketTransport({ ws, taskId })` / `createHttpPollingTransport({ taskId, intervalMs })`，统一接口 `subscribe(handler) → unsubscribe()`。
- [ ] 单测：通过 mock transport 验证 service 行为。

### M5-T2 commentSyncService

- [ ] `createCommentSyncService({ store, log, transport, fetchSince })`：
  - 内部状态：`lastSeen Map<taskId, seq>`、`processed Set<commentId>`（按 task 维度限容 1000 条）；
  - `applyEvent(event)`：校验 → 去重 → `store.upsertComment` / `deleteComment` → 写 event log；
  - `runConvergencePull(taskId)`：`fetchSince(taskId, lastSeen[taskId])` → 全量 merge → 更新 lastSeen；
  - `start(taskId)` / `stop()`：transport 生命周期 + 重连后自动 convergence pull。
- [ ] 单测：6 类（正常事件、乱序、重复、删除、HTTP fallback 触发、convergence pull 后 lastSeen 更新）。

### M5-T3 useReviewStore 透传 seq

- [ ] WebSocket message handler 把 `seq` 也传给回调。
- [ ] 兼容旧 callback 签名：`onCommentAdded((data, seq?) => ...)`。

### M5-T4 service 接入

- [ ] 在 `App.vue` 或 `ReviewPanel.vue` `onMounted` 启动 service；`onUnmounted` 停止。
- [ ] flag：`REVIEW_F_COMMENT_SYNC_V2` 默认 false；启用后接管 comment_added，否则保持现有 onCommentAdded 行为。

### M5-T5 HTTP fallback

- [ ] WebSocket 断开 > `WS_FALLBACK_THRESHOLD`（默认 30s）→ 切 HTTP polling（默认 5s 一次）；

## 6. 回退

| 触发条件 | 处置 |

```js

// 或

```

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 后端 `seq` 实现 race（同时 insert 顺序错位） | 用 `(created_at, id)` 复合排序作为伪 seq；service 端做最终 dedupe by id |
| `processed` Set 内存增长 | 按 task 维度 LRU 限容 1000 |
| 多个 ReviewPanel 同时 mount → service 多实例 | service 用 sharedStores 单例，类似 thread store |
| HTTP fallback 期间 WebSocket 又恢复 | 切换前完成 in-flight 请求；切换原子化；记录 event log |
| WebSocket 鉴权过期断开后重连失败 | service 暴露 `onAuthError(callback)`，由 `useUserStore` 触发 token 刷新 |

## 8. 衔接

- M3-T8 CUTOVER：已让 store 成为唯一真源，service 直接写 store
- M4：`annotationKey/reviewRound` 让幂等 key 真值化
- M6 task draft：service 在任务切换时调 `runConvergencePull(newTaskId)`
- M7 双层渲染：service 不影响 confirmed 层（仅写 thread store；confirmed 仍走 record 路径）
