## 2. 接口一：领 token —— `POST /api/auth/token`

PMS 页面 `GetZyModeInfo` 要回给前端的 `token` 从这里领；后续每一个服务端接口（embed-url / workflow sync、verify / delete / cache preload）请求体里的 `token` 也用它。**PMS 不需要、也不持有任何密钥**，只领不签。

**请求（PMS 现在发的原样即可）**

```json
{ "username": "SJ", "project": "AvevaMarineSample", "role": "SJ" }
```

- `project` / `username` 必填（也接受旧键名 `project_id` / `user_id`）
- `role` 可选，只认 `admin / sj / jd / sh / pz`，不区分大小写；其它值 400 `Invalid role`
- `form_id` 可选：传了原样回传（重开已有单据时传），不传由模型中心生成

**回包（2026-09-21 真机）**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9.…",
    "expires_at": 1790064528,
    "form_id": "FORM-88C3B22E9FAE"
  }
}
```

- 成功是 **`code: 0`**（不是 200），HTTP 200；失败 HTTP 400 / 500，`code: -1`，`message` 说明原因
- token 有效期 24 小时（`expires_at` 为 Unix 秒）；过期或 401 时重新领一次即可

## 3. 接口二：换嵌入地址 —— `POST /api/review/embed-url`

PMS 后端 `GetZyModelUrl` 调这个，把回包里的 `relative_path` 与 `query.form_id` 存进单据的 `ModelUrl / ModelFormId`。

**请求**

```json
{
  "project_id": "AvevaMarineSample",
  "user_id": "SJ",
  "workflow_role": "sj",
  "token": "<接口一领到的 token>"
}
```

- `project_id` / `user_id` / `token` 必填；`workflow_role` 为该用户在本单据上的流程角色（兼容旧键名 `role`，两者同传须一致；不接受 `user_role`）
- 重开已有单据时加 `"form_id": "FORM-…"`，回包会带出已绑定的 `task` 与 `lineage`

**回包（2026-09-21 真机，token 已打码）**

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "relative_path": "/review/3d-view",
    "token": "eyJ…",
    "query": { "form_id": "FORM-82F167649230", "is_reviewer": false },
    "lineage": { "form_id": "FORM-82F167649230" },
    "form": { "form_id": "FORM-82F167649230", "exists": true }
  }
}
```

**拼 iframe 地址**

```text
http://123.57.182.243 + data.relative_path + "?user_token=" + token + "&form_id=" + data.query.form_id + "&user_id=" + HumanCode
```

例：`http://123.57.182.243/review/3d-view?user_token=eyJ…&form_id=FORM-82F167649230&user_id=SJ`

## 6. 报错对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| PMS 页面 `GetZyModelUrl` 回「接口连通失败，异常信息：」 | PMS 服务器那一跳没拿到 200：地址配错（多半还是 `:3100`）、出口不通、或下面两种 | 先跑第 5 节自检 |
| HTTP 401 `{"code":401,"message":"unauthorized"}` | 请求体里的 `token` 不是接口一领的（或已过期） | 重新领 token 再调 |
| HTTP 400 `Invalid role` / `Missing required field` / `Failed to parse the request body as JSON` | 请求体字段或格式不对 | 按第 2 节校对 |
| 连接被拒（或经代理时看到 502） | 地址带的端口没人听（3100 在 2026-09-21 17:00 前就是这样） | 用 80；或确认 3100 仍在监听 |
| `GetZyModeInfo` 回 `{"ip_addr":"","token":""}` | PMS 后端按 `ModelRootUrl` 去领 token 失败，被吞成空串（2026-09-21 16:26 实测：`ModelRootUrl=…:3100` 而 3100 没人听；17:00 nginx 加听 3100 后同一请求 234 ms 回 `{"ip_addr":"http://123.57.182.243","token":"eyJ…"}`） | 让 `ModelRootUrl` 指向一个活着的端口 |

排查时可请洲影侧看模型中心日志：每次请求到达都会有一行 `Token request: …` / `Embed URL request: …`；一行都没有，说明请求根本没到模型中心。

2. **form_id 分叉**：每次调用 PMS 后端都重新去模型中心 `POST /api/review/embed-url` 领一个新的 `form_id`（模型中心侧因此多出 `FORM-A423F4EEF420`、`FORM-B9B40B822B20` 等孤儿单据存根）。库里存的是第 1 次的 `ModelFormId = FORM-A423F4EEF420`，页面 iframe 却用了后一次的 `FORM-B9B40B822B20`。后果：设计人在三维里「发起编校审」建的任务挂在 B9B4…；PMS 之后按单据记录的 A423… 调 `workflow/verify` / `workflow/sync`，模型中心找不到任务（`form_exists=true, task_created=false` 或 `REVIEW_FORM_NOT_FOUND`），流程推不动；校核人从列表双击打开拿到的也是 A423… 的空上下文。这就是《新的三维校审流程分析》§8.6 预警过的分叉，现在有了实证。
3. 在 3100 没人听的那几天，这三次调用全部「接口连通失败」，表现为弹窗一直空白——即本清单 §6 第一行。

**建议改法（PMS 侧）**

- `GetZyModelUrl` 一张新单只调一次：成功后置标记 / 跳转 EditForm 后不再触发；`ModelFormId` 非空即跳过。
- 落库改幂等：已有该 `Id` 就 `UPDATE ModelUrl / RelativePath / ModelFormId`（或 `INSERT … ON DUPLICATE KEY UPDATE`），不要把 SQL 原文回给前端。
- 重开 / 刷新已有单据时，把库里的 `ModelFormId` 作为 `form_id` 传给模型中心 `embed-url`（接口支持：带 `form_id` 会返回同一单据及已绑定的 `task` / `lineage`），iframe 的 `form_id` 只从库里取，不再现领。
- `GetZyModeInfo`（领 token）与 form_id 无关，保持现状即可。

**模型中心侧配合**：无需改接口。可选：对同一 `project_id + user_id` 数秒内的重复 `embed-url` 做去重日志告警，便于双方对账。那两条孤儿存根（A423…、B9B4…）与 PMS 测试单 `fc894ff9-…` 可在 PMS 删单时经 `/api/review/delete` 一并清理。
