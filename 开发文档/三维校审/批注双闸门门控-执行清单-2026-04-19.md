## 0. 阶段目标

1. **闸门 1（设计完整性）**：sj 节点 submit 时，若存在 `resolutionStatus=open` 批注则**硬拒绝**；
2. **闸门 2（校审全通过）**：jd / sh / pz 节点 submit 时，若 `agreed < total` 则**后端自动 `return_to_sj`**，UI Toast 提示；
3. **前后端双层防御**：前端 UI 预检（可用性）+ 后端 gate（安全性），flag 灰度上线；
4. **审计完整**：每次自动 return 在 `review_workflow_history` 留记录；
5. **历史任务零影响**：flag 默认 false，旧任务不受冲击。

### 非目标

- 不在本阶段改 `resolutionStatus / decisionStatus` 的字段结构（等 M4）；
- 不做批注的分页 / @人 / 富文本（产品演进项）；
- 不动 `return_to_node` 的手动路径（保留给审核员主动退回）。

## 3. 数据契约

### 3.1 SurQL 聚合函数（后端新增）

```surql
DEFINE FUNCTION fn::annotation_review_summary($task_id: string) {
  LET $records = SELECT * FROM review_records WHERE task_id = $task_id;
  LET $all_ann = array::flatten(
    $records.map(|$r| array::concat(
      $r.annotations ?? [],
      $r.cloud_annotations ?? [],
      $r.rect_annotations ?? [],
      $r.obb_annotations ?? []
    ))
  );
  RETURN {
    total:    array::len($all_ann),
    open:     array::len($all_ann.filter(|$a|
                 $a.reviewState.resolutionStatus = NONE
                 OR $a.reviewState.resolutionStatus = "open")),
    agreed:   array::len($all_ann.filter(|$a| $a.reviewState.decisionStatus = "agreed")),
    rejected: array::len($all_ann.filter(|$a| $a.reviewState.decisionStatus = "rejected")),
    pending:  array::len($all_ann.filter(|$a|
                 $a.reviewState.decisionStatus = NONE
                 OR $a.reviewState.decisionStatus = "pending"))
  };
};
```

### 3.2 新增 API

| Endpoint | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/api/review/tasks/{id}/annotation-summary` | GET | - | `{ code, data: { total, open, agreed, rejected, pending } }` |

供前端获取聚合用于 UI 预检；后端 gate 直接调 `fn::annotation_review_summary` 不走 HTTP。

### 3.3 `submit_to_next_node` 错误体

```json
// 闸门 1 失败
{
  "success": false,
  "error_message": "尚有 N 条批注未回复（处于待处理状态），请先逐条标记「已修改」或「不需解决」",
  "gate": "sj_all_replied",
  "summary": { "total": 40, "open": 3 }
}

// 闸门 2 失败 + 自动 return
{
  "success": false,
  "message": "「校对」节点发现 2 条未通过批注（pending=0 rejected=2），按流程已自动驳回到编制节点",
  "gate": "review_all_agreed_auto_return",
  "summary": { "total": 40, "agreed": 38, "rejected": 2, "pending": 0 }
}
```

HTTP 状态：闸门 1 失败 `409 CONFLICT`；闸门 2 失败也是 `409`，但任务已写库为 `current_node=sj`。

## 7. 风险与回退

| 风险 | 对策 |
|---|---|
| 已 `approved` 老任务含 `pending` 批注，后端自动 return 错误触发 | flag 默认 false；启用后只对 `status in (submitted, in_review)` 生效 |
| SurQL UDF 在生产部署权限不足 | fallback 用后端 Rust 端内存计算：`SELECT annotations FROM review_records WHERE task_id=$id` 取回后用 serde 过滤 |
| 审核员误点 submit 被自动退回，心理预期不符 | UI Toast 明确 "已自动驳回到编制节点"，保留 review_workflow_history 可查 |
| 前端预检与后端 gate 时间差漏判（批注瞬间被改） | 以后端为准，前端 disabled 仅是可用性优化 |
| 批量确认误用 | 二次确认对话框 + 仅 `pz`/admin 可见 |

回退命令：

```bash
# 运维端（后端）：
$env:REVIEW_GATE_SJ_ALL_REPLIED='0'
$env:REVIEW_GATE_REVIEW_ALL_AGREED='0'
# 重启 web_server

# 用户端（前端）：
localStorage.setItem('review.force_legacy', '1')
# 或
localStorage.setItem('review.flag.REVIEW_GATE_REVIEW_ALL_AGREED', '0')
```
