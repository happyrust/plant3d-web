## 1. 阶段目标

1. UI 改读 `commentThreadStore`，inline `annotation.comments` 不再进入渲染路径；
2. 写路径（comment create / update / delete）直接调 store API，inline 字段由 store→inline mirror 自动维护；
3. 完整的回退路径：`force_legacy=1` 或 `REVIEW_C_COMMENT_THREAD_STORE_CUTOVER=0` 时，渲染立刻回到 inline 源；
4. 与 M5（`commentSyncService` WebSocket 接管）的契约对齐：`store.upsertComment` 成为唯一写入入口。

非目标：

- 不删除 `useToolStore.comments` 字段（留 M7 双层渲染时一起退役）；
- 不改动 `useToolStore.setAnnotationComments` 等 inline API（兼容期保留）；
- 不引入 `annotationKey` v2 真消费（M4 才进入契约）；
- 不接管 WebSocket（M5/F）。

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| store→inline 投影写回时 `useToolStore` 触发自身 watch 链路造成无限循环 | `projectStoreToInline` 在写回前比对哈希；`syncInlineToStore` 内已有 fingerprint，二者互斥 |
| 多个 ReviewCommentsTimeline 实例同时挂 watch 重复 sync | sharedStores 单例 + fingerprint 去抖；`changed=false` 时不 notify |
| CUTOVER 期间 confirm 流程依赖 inline `annotation.comments` 字段做 replay | M3 阶段保留 inline 投影，replay 路径不变；M7 双层渲染时再处理 |
| WebSocket comment_added 写 inline，CUTOVER 后 store 与 inline 短暂不一致 | M5 commentSyncService 必须**先**写 store 再投影；M3-T8 文档明确该约定 |
| 用户在 CUTOVER 期间手动 `localStorage` 写 force_legacy 后又关闭 | UI 在 force_legacy 切换时强制重读 `allComments` computed；增加一个 `watchEffect` 监听 `localStorage` 变化（最低限度） |

## 6. 衔接

- M5（commentSyncService）依赖本阶段产出的 `store.upsertComment` 单一入口
- M7（draft / confirmed 双层渲染）会基于 thread store + snapshot 把 inline `annotation.comments` 字段彻底退役
- M4（后端 metadata 扩展）到位后，CUTOVER 阶段的 `SnapshotComment.annotationKey/workflowNode/reviewRound` 真值化，store 可按轮次 / 节点过滤
