## 0. 准入条件

- [ ] M5 commentSyncService 在生产稳定 ≥ 1 周

## 1. 阶段目标

1. 校审模式下 scope = `project=xxx|db=yyy|task=zzz`；非校审保持原 scope（建模工具不受影响）；
2. 任务切换：自动加载新 task 草稿、保存旧 task 草稿，互不串扰；
3. 退出校审：scope 回到 `project + db`，原通用建模草稿可继续；
4. designer "返回重提" continuity：同 `taskId` 多次进入草稿可恢复；
5. flag 灰度：`REVIEW_G_TASK_SCOPED_DRAFT` 默认 false，开启后启用 task scope；关闭即回退。

## 2. 现状（盘点）

```ts
// src/composables/useToolStore.ts:370
function getCurrentStorageScope(): string {
  const params = new URLSearchParams(window.location.search);
  const project = getOutputProjectFromUrl() || params.get('project_id') || DEFAULT_STORAGE_SCOPE;
  const dbnum = params.get('show_dbnum') || '__all__';
  return `project=${project}|db=${dbnum}`;
}
```

问题：

- 同 project / db 下多个 review task 共用一份 storage → 切换任务时草稿串扰
- designer 返回任务后再次打开 → 旧草稿可能被新任务覆盖
- 嵌入 PMS 模式下 formId/taskId 不进入 scope

## 6. 回退

| 触发条件 | 处置 |
| --- | --- |
| 草稿丢失用户报告 ≥ 1 例 | 立即关 `REVIEW_G_TASK_SCOPED_DRAFT`，迁移数据已保留兜底 |
| 性能退化（task 切换时 load > 100ms） | 关 flag |

回退命令：

```js
localStorage.setItem('review.flag.REVIEW_G_TASK_SCOPED_DRAFT', '0');
// 或
localStorage.setItem('review.force_legacy', '1');
```

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 循环依赖：useToolStore ↔ useReviewStore | 用注入式 `setDraftScopeProvider`，由 `App.vue` 在 init 时把 reviewStore.currentTask 提供给 useToolStore |
| 切换任务时 save / load 时序错乱 | watch 中 await save 完成再 load；用 lock 防并发 |
| URL 不带 project 时 scope 退化为 default | 与现状一致；M6 不改 |
| 迁移数据膨胀（每 task 一份草稿） | localStorage 用户级有 5MB 限制；超阈值时 LRU 清理 30 天前的 task scope |
| 任务 id 包含特殊字符破坏 scope key | scope 拼接用 `encodeURIComponent` |

## 8. 衔接

- M5：scope 切换后 commentSyncService 自动 convergence pull 新 task
- M7 双层渲染：scope 中 draft 部分对应 draft layer；confirmed layer 仍按 task records
