- [ ] 评论真源已切到 `commentThreadStore`，`dual_read_diff` 滚动 24h = 0

## 1. 阶段目标

1. 让 `annotationKey`（v2 权威）、`workflowNode`（与 task.currentNode 区分）、`reviewRound`（任务级单调递增）三类字段进入：
   - `review_comments` 表写库 + 读出
   - `review_records` 表写库 + 读出
   - `review_tasks` 表新增 `current_round`
   - `/api/review/workflow/sync` 聚合返回
   - `/api/review/comments/*` 创建 / 查询响应
   - `/api/review/records/*` 创建 / 查询响应
   - WebSocket 事件 `comment_added` / `record_created` 等
2. 兼容窗口：双字段并存 ≥ 2 个发版周期；旧字段不删；前端 adapter 在缺新字段时按 M2 v1 兜底
3. 与 M3 闭环：`SnapshotComment.annotationKey` / `SnapshotComment.reviewRound` 真值化后，`commentThreadStore` 内可按轮次 / 节点过滤

## 3. 字段约定（权威）

| 字段 | 类型 | 生成方 | 写入时机 | 读取契约 |
| --- | --- | --- | --- | --- |
| `annotation_key` | `String`（UUID v7 hex） | 后端 | 创建批注 / 评论时；评论可继承所属 annotation 的 key | 响应字段统一为 `annotationKey`（camelCase） |
| `task_id` | `String` | 后端 | 创建评论时由 annotation_id 反查 review_records → task_id 注入 | 响应字段 `taskId` |
| `form_id` | `String` | 后端 | 同上反查 review_tasks.form_id | 响应字段 `formId` |
| `workflow_node` | `String`（`sj`/`jd`/`sh`/`pz`） | 后端 | 创建时取 task.current_node 作为"该条 record/comment 归属的节点" | 响应字段 `workflowNode`，与 `currentNode` 区分（currentNode 是任务"当前正在哪个节点"，workflowNode 是"这条记录属于哪个节点"） |
| `review_round` | `Integer`（从 1 开始） | 后端 | 创建时取 task.current_round | 响应字段 `reviewRound`；不可逆 |
| `task.current_round` | `Integer` | 后端 | 退回（return_to_designer）时原子 `+= 1` | 不直接对外，仅作为创建时的填充源 |

**关键约定**：

- `workflow_node` ≠ `current_node`：前者属于该条 record/comment，**不随 task 进展变化**；后者属于 task 整体，**会随节点流转变化**。
- 旧批注 / 评论不迁移 `review_round`：`reviewRound = 1` 的条目在 `currentRound = 2` 时仍为 1。前端"仅本轮 / 累计全部"过滤需支持。
- `annotation_key` 在 v2 启用前由前端 v1（补遗 §3）兜底；v2 启用后后端写回，前端覆盖。

## 4. 数据库迁移

### 4.1 review_tasks 增字段

```surql
DEFINE FIELD current_round ON review_tasks TYPE int DEFAULT 1 ASSERT $value >= 1;
UPDATE review_tasks SET current_round = 1 WHERE current_round IS NONE;
```

### 4.2 review_comments 增字段

```surql
DEFINE FIELD annotation_key ON review_comments TYPE option<string>;
DEFINE FIELD task_id        ON review_comments TYPE option<string>;
DEFINE FIELD form_id        ON review_comments TYPE option<string>;
DEFINE FIELD workflow_node  ON review_comments TYPE option<string>;
DEFINE FIELD review_round   ON review_comments TYPE option<int>;

DEFINE INDEX review_comments_task_id_idx        ON review_comments FIELDS task_id;
DEFINE INDEX review_comments_annotation_key_idx ON review_comments FIELDS annotation_key;
```

### 4.3 review_records 增字段

```surql
DEFINE FIELD review_round ON review_records TYPE option<int>;
-- workflow_node 暂复用 current_node；新增独立字段以避免语义漂移：
DEFINE FIELD workflow_node ON review_records TYPE option<string>;
```

注释：现有 `current_node` 字段保持原义（"上一次 confirm 时所在的 currentNode"）；新字段 `workflow_node` 表示"该 record 归属的节点"。两者在大部分场景值相同；但在跨节点 confirm（极少）时区分。

## 5. API 契约扩展

### 5.1 POST /api/review/comments

请求：

```diff
{
  "annotationId": "...",
  "annotationType": "text|cloud|rect|obb",
  "authorId": "...",
  "authorName": "...",
  "authorRole": "sj|jd|sh|pz",
  "content": "...",
  "replyToId": "..."?,
+ "annotationKey": "..."?      // 前端 v1 兜底；后端会覆盖
}
```

响应（向后兼容旧字段）：

```diff
{
  "success": true,
  "comment": {
    ...原字段,
+   "annotationKey": "...",
+   "taskId": "...",
+   "formId": "...",
+   "workflowNode": "sj|jd|sh|pz",
+   "reviewRound": 2
  }
}
```

### 5.2 POST /api/review/records（confirmed_record_create）

请求：

```diff
{
  ...原字段,
+ "annotations": [{ ...原字段, "annotationKey": "..." }, ...]
+ // cloud / rect / obb 同理
}
```

响应：

```diff
{
  "success": true,
  "record": {
    ...原字段,
+   "reviewRound": 2,
+   "workflowNode": "sj"
  }
}
```

### 5.3 GET /api/review/workflow/sync

每条 `records[i]` + `annotationComments[i]` 在响应中带新字段（同 5.1 / 5.2）。

### 5.4 WebSocket 事件

```diff
{
  "type": "comment_added",
  "payload": {
    "comment": { ...含 annotationKey / taskId / workflowNode / reviewRound }
  }
}
```

## 8. 兼容窗口与回退

| 场景 | 行为 |
| --- | --- |
| 前端旧版（不带新字段） | 后端写库时新字段 NULL；查询响应字段省略；前端 v1 兜底 |
| 后端旧版（不返回新字段） | 前端 adapter 检测缺字段 → snapshot 字段 undefined → UI 不显示新过滤位 |
| 切回 v1 | `localStorage['review.flag.REVIEW_D_ANNOTATION_KEY_V2']='0'`；写路径仍向后端透传 v1 key 用于审计 |
| 数据回滚 | 仅删除新字段不删旧字段；DROP FIELD review_comments.annotation_key 等 |

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| review_round 自增竞争（多人同时退回） | 后端用 SurQL 事务 + UPSERT 原子自增；增加幂等 key |
| annotation_key v1 与 v2 在迁移期不一致 | 双字段并存 ≥ 2 周期；前端审计模块比对告警 |
| 旧 comment 缺 annotation_key 导致 thread store 归并失败 | 后端 backfill：根据 (annotation_id, annotation_type, task_id) 反推 v1 key 写回 |
| workflow_node 与 current_node 误用 | 文档明确两者语义；前端 lint rule（M4-T9 可选）：`useReviewStore.currentTask.currentNode` 不得直接赋给 `SnapshotAnnotation.workflowNode` |
| 前后端发布顺序错位 | 后端先发布（兼容老前端）；前端再发布；间隔 ≥ 24h |

## 10. 衔接

- M5 commentSyncService：`annotationKey` 成为 WebSocket 幂等 key；`reviewRound` 用于服务端去重
- M6 task-scoped draft：`annotationKey` 让 draft 在 task 切换时按 key 而非 id 归并
- M7 双层渲染：`workflowNode` 用于 confirmed 层按节点分组渲染
