# 批注体系重构 Mission 说明

> 日期：2026-04-19  
> 适用仓库：`plant3d-web`、`plant-model-gen`  
> 用途：为下一次重新发起的 annotation refactor mission 提供简洁、可执行的任务边界说明。

## 1. Mission 目标

在不打断现有 reviewer / designer 主链路的前提下，重新启动“批注体系重构”任务，完成以下主线：

- 统一 `ReviewSnapshot` 恢复语义；
- 将 comment thread 从 annotation inline 结构中解耦；
- 扩展后端 metadata 契约以支撑稳定 restore / round / node 语义；
- 完成 realtime convergence、task-scoped drafts、draft/confirmed dual-layer rendering。

## 2. 为什么需要重开

本轮不是因为方案缺失，而是因为 **旧 mission artifacts 虽然存在且内容有效，但 mission runner 未能成功启动**。继续在原 mission 运行态上排障，成本高且不利于恢复执行节奏，因此需要：

- 用新的 planning package 重新组织输入；
- 只复用已有文档、feature 分解、validation 合同；
- 避免继承旧 mission 的不确定运行状态。

## 3. 推荐的 Mission 边界

### 包含

- `plant3d-web` 与 `plant-model-gen` 的 annotation refactor 主线；
- 原计划定义的 7 个 milestone；
- 恢复统一、评论解耦、契约扩展、实时收敛、task draft 隔离、双层渲染；
- 与 Mission 直接相关的单元测试、组件验证、接口验证、浏览器验证。

### 不包含

- mission runner 本身的实现排障；
- 与批注重构无关的 reviewer/designer 额外功能扩展；
- README、通用文档站点、无关基础设施改造；
- 无验证价值的大范围重构或额外性能优化项目。

## 5. Worker / Skill 建议

建议按 milestone 或 feature 粒度拆 worker，避免单 worker 过大：

- M1 / M2：`review-workbench-worker`、`review-annotation-worker`
- M3 / M5：`review-collaboration-worker`
- M4：`review-annotation-worker` + 后端契约协作 worker
- M6：`review-annotation-worker`、`designer-tracking-worker`
- M7：`review-annotation-worker`
- 需要总体验证时：`requesting-code-review`、`verification-before-completion`

如果新 Mission 支持先规划后执行，建议先生成 milestone 级任务单，再逐个放行。

## 6. 验证策略

### 6.1 前端验证

- `npm run lint`
- `npm run type-check`
- `npm test`
- 按改动点补充 focused Vitest / component tests
- 浏览器验证 reviewer workbench、designer returned-task、restore / replay / thread 行为

### 6.2 后端 / 契约验证

- 使用真实 HTTP/curl 验证 records/comments/workflow-sync 契约；
- 对 metadata 扩展阶段做兼容前后对比；
- 对 websocket 事件做 targeted refresh、reconnect、HTTP fallback 验证。

### 6.3 里程碑式验收

- M1：字段语义、feature flag、兼容窗口冻结；
- M2：三类 restore 结果一致；
- M3：评论真源独立，线程行为正确；
- M4：metadata 契约稳定可读；
- M5：realtime convergence 不重复、不乱序；
- M6：task draft 不串扰，returned-task continuity 保持；
- M7：draft / confirmed 双层分离且可回退。

## 7. 重开后优先落地的前 3 个 feature

1. **ReviewSnapshot 恢复统一入口**  
   先把 task restore、workflow/sync restore、import restore 收敛到同一 snapshot 语义层，这是后续所有改造的基础。

2. **detached comment source / thread store**  
   先解开 annotation inline comments 的强耦合，避免后续 round、node、realtime 行为继续堆在旧结构上。

3. **records/comments/workflow-sync metadata 扩展**  
   让 `annotationKey`、`workflowNode`、`reviewRound` 进入契约，为实时收敛、task continuity、双层渲染提供稳定锚点。

## 8. 建议的启动方式

- 以这份 Mission 说明作为新的 mission brief；
- 首批只装载 M1/M2 所需 worker 与验证要求；
- 确认 runner 能正常启动后，再继续追加后续 milestone；
- 每完成一个 milestone，就把“输入/输出/验证结果/遗留风险”写回新 mission 包，方便再次中断时继续重开。
