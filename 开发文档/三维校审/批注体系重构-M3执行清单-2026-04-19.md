## 1. 阶段目标

1. 引入独立 **comment thread store**，按 `(annotationType, annotationId)` 索引；
2. ReviewSnapshot 内 `SnapshotComment[]` 与 thread store 之间形成单向初始化关系；
3. 通过 `REVIEW_C_COMMENT_THREAD_STORE_DUAL_READ` flag 让 `ReviewCommentsTimeline` 在 DUAL_READ 阶段同时读 inline + thread store 并对比，发现差异告警；
4. CUTOVER 后 `ReviewCommentsTimeline` 仅消费 thread store；inline `comments` 字段降级为只读投影。

非目标：

- 本阶段不动后端契约（M4 才扩字段）；
- 本阶段不接入 WebSocket（M5/F 才统一 commentSyncService）；
- 本阶段不引入 `annotationKey` v2（M4）；
- 本阶段不动评论编辑/删除 UI 逻辑，只做读路径解耦。

## 3. CommentThread 字段约定

复用 M2 的 `SnapshotComment` 作为 entry 主体；新增以下结构：

```ts
type CommentThreadKey = `${SnapshotAnnotationType}:${string}`;

interface CommentThreadEntry extends SnapshotComment {
  /** 由 store 在 upsert 时填入。供线程内顺序对比与去重。 */
  threadOrder: number;
}

interface CommentThread {
  key: CommentThreadKey;
  annotationId: string;
  annotationType: SnapshotAnnotationType;
  entries: ReadonlyArray<CommentThreadEntry>;
}

interface CommentThreadIndex {
  byKey: ReadonlyMap<CommentThreadKey, CommentThread>;
  /** 线程数量（不同 annotation 数）。 */
  size: number;
  /** 全部 entries 数量；用于诊断与基线对比。 */
  totalEntries: number;
}
```

约束：

- `threadOrder` 仅作为同 thread 内稳定排序键；不参与 hash；
- store 不持有任何 inline `annotation.comments` 字段，避免与旧真源混淆；
- store 在初始化时按 `createdAt` ASC 排序 entries；后续 upsert 维持时间序。

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| store 初始化与 inline 评论顺序不一致 | mergeFromSnapshot 内统一按 `(createdAt ASC, commentId ASC)` 排序，inline 投影端同样规则 |
| 多入口 restore 重复 mergeFromSnapshot 导致 listener 抖动 | mergeFromSnapshot 比对 incoming snapshot 的 entries 哈希，无变化时跳过 notify |
| 评论编辑路径仍写到 inline | M3 仅做读路径解耦，写路径在 M4 后端字段就绪后统一改造；中间期 store 提供 `upsertComment(forceFromInline=true)` 兼容 |
| `useToolStore` 内 `comments` 字段保留 → 长期重复内存占用 | M3-T6 CUTOVER 后将 inline 字段标记 deprecated，M7 viewer 双层渲染再彻底移除 |

## 6. 后续衔接

- M4 后端 metadata 扩展到位后，`SnapshotComment.annotationKey/workflowNode/reviewRound` 真正进入索引，thread store 可按轮次过滤；
- M5 commentSyncService 接管 WebSocket 后，`store.upsertComment` 直接成为唯一写入路径；
- M7 双层渲染时，draft layer 与 confirmed layer 都通过 store 拉评论，UI 无需关心来源。
