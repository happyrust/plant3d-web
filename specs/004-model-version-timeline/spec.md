# Feature Specification: 模型版本时间线与历史模型树（Model Version Timeline）

**Feature Branch**: `004-model-version-timeline`

**Created**: 2026-07-18

**Status**: Draft

**Input**: User description: "结合 ../plant-model-gen 的版本管理能力，在 plant3d-web 前端加版本管理功能：用时间线展示模型版本演进，并支持查看不同时间点的模型树（含差异标注、历史快照、双版本对比）。"

## 功能清单总览（按落地分期）

| 分期 | 功能 | 对应需求 |
|---|---|---|
| Phase 1（P1） | 版本时间线面板：垂直时间轴、按天分组、版本卡片（标签/时间/双轴状态徽章/diff 摘要） | FR-001…FR-008 |
| Phase 1（P1） | 项目 / dbnum / 分支筛选 | FR-006 |
| Phase 1（P1） | 树内差异标注：增/删/改徽章、幽灵节点、差异筛选、属性 before/after | FR-009…FR-014 |
| Phase 2（P2） | 历史快照模式（单树时间旅行）：版本下拉、只读横幅、快照缓存、过期降级 | FR-015…FR-020 |
| Phase 2（P2） | 3D 联动：加载所选版本场景、树/3D/时间线三方选中同步 | FR-021…FR-023 |
| Phase 3（P2/P3） | 双版本并排对比（A|B 钉选、双树对齐联动、差异行高亮） | FR-024…FR-028 |
| Phase 3（P3） | 3D 视口底部时间刻度条（scrubber，逐版本步进/播放） | FR-029…FR-030 |
| 全程 | 质量态守护、锚点入口约束、历史过期与缺锚降级 | FR-031…FR-035 |

## User Scenarios & Testing

### User Story 1 - 浏览版本时间线（Priority: P1）

作为模型审查/设计人员，我可以在一个「版本时间线」面板中按时间顺序浏览某个项目库（dbnum）的发布版本与设计会话锚点，一眼看出每个版本发生的时间、当前状态和变化规模，从而快速回答"这个库最近发生了什么"。

**Why this priority**: 时间线是所有版本功能的统一入口。没有它，用户只能靠 URL 参数或后端诊断页找版本号。

**Independent Test**: 打开含有多个已发布版本的项目，打开版本时间线面板，验证版本按时间倒序分组展示、状态徽章与后端记录一致、点击卡片能看到 diff 摘要。

**Acceptance Scenarios**:

1. **Given** 项目存在多个发布版本，**When** 用户打开版本时间线面板，**Then** 版本按天分组、组内按时间倒序展示，每张卡片显示版本标签（或 release_id）、注册时间与状态徽章。
2. **Given** 某版本处于隔离或降级质量态，**When** 该版本出现在时间线上，**Then** 卡片显示明显区别于正常版本的警示徽章（隔离红 / 降级黄 / 完整绿），且工作流态（如 published/failed）与质量态分开呈现。
3. **Given** 时间线已加载，**When** 用户展开某个版本卡片，**Then** 显示相对上一版本的变化摘要（新增 n / 修改 m / 删除 k），摘要按需懒加载。
4. **Given** 库中存在设计会话锚点，**When** 用户切换到"细粒度"刻度，**Then** 时间线在发布版本之间补充展示会话锚点节点。
5. **Given** 项目没有任何版本数据，**When** 用户打开时间线面板，**Then** 显示明确的空态说明而不是空白或报错。

### User Story 2 - 在模型树中查看两个版本的差异（Priority: P1）

作为模型审查人员，我可以在时间线上选定一个版本对（当前 vs 历史，或任意两个版本），让模型树在原有结构上直接标注出增/删/改节点，点开变更节点还能看到属性级 before/after，从而不离开熟悉的树视图就理解版本差异。

**Why this priority**: 树内差异标注复用用户已有的心智模型，是"查看不同时间线的模型树"的最低成本形态，且前端已有增量对比高亮通道可复用。

**Independent Test**: 选定已知差异的版本对，验证树中变更节点出现对应徽章、被删除节点以幽灵形态回插原位、筛选器能只看某类变更、属性面板展示 old/new 差异。

**Acceptance Scenarios**:

1. **Given** 用户在时间线上选定版本对，**When** 差异应用到模型树，**Then** 新增节点带"增"徽章、修改节点带"改"徽章、删除节点以灰色删除线幽灵节点显示在原父节点下。
2. **Given** 树内差异已生效，**When** 用户使用"全部/新增/修改/删除"筛选，**Then** 树只保留所选类别的变更节点及其祖先路径。
3. **Given** 用户点击一个"改"节点，**When** 属性差异加载完成，**Then** 面板并排显示该元素的变更前/变更后属性值，并标出差异行。
4. **Given** 差异数量很大（数千节点），**When** 差异应用到树，**Then** 界面保持可交互（虚拟滚动），不出现长时间卡死。
5. **Given** 差异模式开启，**When** 用户退出差异模式，**Then** 树恢复常规展示，徽章与幽灵节点全部清除。

### User Story 3 - 历史快照模式：把模型树切到任意历史版本（Priority: P2）

作为设计人员，我可以从时间线选择一个历史版本（发布版本或会话锚点），让整棵模型树切换为该时刻的快照（只读），看完后一键回到最新版本，从而复原"当时模型长什么样"。

**Why this priority**: 时间旅行是版本管理的核心价值，但依赖 US1 的版本选择入口，且需要只读守护，故排在 P1 之后。

**Independent Test**: 选择一个历史版本进入快照模式，验证树内容与该版本一致、出现只读横幅、编辑/生成类操作被禁用、退出后恢复最新树。

**Acceptance Scenarios**:

1. **Given** 用户在时间线上选择"查看此版本树"，**When** 快照加载完成，**Then** 模型树整体切换为该版本内容，顶部出现"正在查看历史版本 X（只读）"横幅。
2. **Given** 处于历史快照模式，**When** 用户尝试编辑、生成或其它写操作入口，**Then** 这些入口不可用或明确提示只读。
3. **Given** 用户在多个历史版本间来回切换，**When** 再次进入看过的版本，**Then** 树数据命中缓存并快速展示（无需重新全量拉取）。
4. **Given** 站点配置了有限历史保留窗口且所选时刻已过期，**When** 快照加载失败（历史已过期），**Then** 界面提示"历史已过期，请改用发布版本粒度"并引导选择最近的发布版本。
5. **Given** 所选 sesno 无法解析到固化锚点，**When** 解析失败，**Then** 界面提示锚点缺失并回退到最近可用锚点或发布版本，不允许绕过锚点直查历史。

### User Story 4 - 双版本并排对比（Priority: P2）

作为模型审查人员，我可以在时间线上把两个版本钉选为 A 和 B，进入左右双树并排对比视图（按元素对齐、滚动与展开联动、差异行红绿黄高亮），同时可让 3D 视图并排渲染两个版本的差异构件，从而做正式的版本审查。

**Why this priority**: 双树对比是重交互功能，价值大但成本高；树内标注（US2）已能覆盖大部分日常场景。

**Independent Test**: 钉选两个已知差异版本为 A/B，验证双树按 refno 对齐、一侧滚动/展开另一侧联动、差异行按增/删/改着色、3D 可并排显示差异构件。

**Acceptance Scenarios**:

1. **Given** 用户在时间线卡片上分别执行"设为对比 A"与"设为对比 B"，**When** 两者都已钉选，**Then** 出现进入对比视图的明确入口，且 A/B 徽标在时间线上可见。
2. **Given** 双树对比视图打开，**When** 用户滚动或展开一侧的节点，**Then** 另一侧同步滚动/展开到对应元素。
3. **Given** 双树对比视图打开，**When** 存在增/删/改差异，**Then** 对应行分别以新增绿/删除红/修改黄高亮，仅一侧存在的元素在另一侧留出对位空行。
4. **Given** 版本对可比性检查未通过（如未发布、跨库），**When** 用户尝试进入对比，**Then** 界面展示后端给出的原因与建议动作，而不是静默失败。
5. **Given** 对比的某一版本处于隔离质量态，**When** 进入对比视图，**Then** 显示显著警示，防止用户把隔离版本误当基准。

### User Story 5 - 时间刻度条播放（Priority: P3）

作为演示/汇报场景的用户，我可以在 3D 视口底部展开一个时间刻度条，每个版本一个刻度点，拖动或点击切换版本，并可按时间顺序自动步进播放，直观展示模型演变过程。

**Why this priority**: 演示向增强功能，依赖 US1/US3 的版本加载能力，独立成期最后交付。

**Independent Test**: 打开刻度条，拖动到任一版本刻度，验证 3D 场景切换到该版本；点击播放，验证按时序逐版本步进。

**Acceptance Scenarios**:

1. **Given** 刻度条开启，**When** 用户点击/拖动到某个版本刻度，**Then** 3D 场景加载该版本，当前刻度高亮，时间线面板选中状态同步。
2. **Given** 用户点击播放，**When** 播放进行中，**Then** 场景按版本时间顺序逐个切换，可随时暂停；播放到末尾自动停止。
3. **Given** 某个版本场景加载较慢，**When** 播放推进到该版本，**Then** 播放器等待加载完成或显示加载态，不跳帧也不卡死界面。

### Edge Cases

- 项目/库没有任何发布版本或锚点（空时间线）。
- 版本处于 failed / staged 等未发布工作流态：可见但不可作为快照/对比目标（或显著降权）。
- 版本质量态为 quarantined_visual / degraded_visual / patch_only / non_visual：徽章区分、对比与快照时警示。
- 历史保留窗口有限导致 snapshot 过期（后端返回明确过期错误）。
- sesno 解析不到固化锚点（锚点缺失）。
- 差异规模极大（数千至数万元素）导致的渲染与内存压力。
- 同一 dbnum 存在多分支（branch_id）时的时间线分组与过滤。
- 版本对跨项目/跨 dbnum：不可比，需给出后端 readiness 的原因。
- 快照/diff 请求进行中用户切换版本或关闭面板（请求竞态与取消）。
- 删除节点的父节点本身也被删除（幽灵节点的挂载位置）。

## Requirements

### Functional Requirements

**时间线展示（US1）**

- **FR-001**: 系统必须提供「版本时间线」面板，可从功能区入口打开/关闭，与现有面板体系一致地停靠。
- **FR-002**: 时间线必须按时间倒序展示所选项目 + dbnum 的发布版本，并按天分组。
- **FR-003**: 每个版本节点必须展示：版本标签（缺省回退 release_id）、注册/创建时间、dbnum。
- **FR-004**: 每个版本节点必须以两个独立维度展示状态：工作流生命周期（staged/validating/assets_materialized/indexed/published/failed）与质量态（complete_visual/quarantined_visual/degraded_visual/patch_only/non_visual），不得合并为单一徽章。
- **FR-005**: 版本卡片展开时必须懒加载并显示相对前一版本的差异摘要（新增/修改/删除数量）。
- **FR-006**: 时间线必须支持按项目、dbnum、分支（branch_id）筛选。
- **FR-007**: 时间线必须支持"发布版本"与"含会话锚点"两档粒度切换；锚点节点视觉上区别于发布版本节点。
- **FR-008**: 空数据、加载中、加载失败三种状态必须有明确的界面呈现。

**树内差异标注（US2）**

- **FR-009**: 用户必须能从时间线选定版本对（A→B），并把差异应用到当前模型树。
- **FR-010**: 树中新增/修改节点必须显示对应徽章；删除节点必须以幽灵形态（灰色删除线、不可选中定位 3D）回插到原父节点下。
- **FR-011**: 必须提供"全部/新增/修改/删除"差异筛选；筛选时保留匹配节点的祖先路径以维持树形结构。
- **FR-012**: 点击修改节点必须能查看该元素的属性级 before/after 差异。
- **FR-013**: 差异应用与清除必须不破坏树的既有功能（搜索、类型过滤、选中联动 3D）。
- **FR-014**: 大差异集（≥5000 条）必须保持界面可交互；差异合并计算不得阻塞主线程造成秒级卡顿。

**历史快照模式（US3）**

- **FR-015**: 用户必须能把模型树整体切换到所选发布版本或锚点时刻的快照。
- **FR-016**: 历史快照模式必须显示持续可见的只读横幅（含版本标识与退出入口），并禁用编辑/生成类操作。
- **FR-017**: 历史树数据必须按版本键缓存，重复进入同一版本时命中缓存。
- **FR-018**: 会话级历史查询必须只经由固化锚点入口（先解析锚点再取快照），禁止绕过锚点直查底层版本存储。
- **FR-019**: 历史已过期（保留窗口外）时必须提示用户并引导降级为发布版本粒度。
- **FR-020**: 锚点缺失时必须提示并提供回退选项（最近可用锚点或发布版本）。

**3D 联动（US3/US4）**

- **FR-021**: 从时间线选择"在 3D 中加载"必须能加载该版本的场景数据。
- **FR-022**: 时间线、模型树、3D 视图三方的当前版本/选中元素状态必须保持同步。
- **FR-023**: 双版本对比时 3D 必须能并排/分色渲染两个版本的差异构件（复用现有 from 蓝 / to 绿约定）。

**双版本并排对比（US4）**

- **FR-024**: 用户必须能在时间线上钉选 A、B 两个版本并进入并排对比视图。
- **FR-025**: 双树必须按元素标识对齐；仅一侧存在的元素在另一侧显示对位占位。
- **FR-026**: 双树滚动与节点展开/折叠必须联动。
- **FR-027**: 进入对比前必须执行版本对可比性检查，不可比时展示原因与建议动作；隔离/降级质量态版本参与对比时必须显著警示。
- **FR-028**: 差异行必须按新增/删除/修改分色高亮，并提供与 US2 一致的差异筛选。

**时间刻度条（US5）**

- **FR-029**: 3D 视口底部必须可展开时间刻度条，每个版本一个刻度点，点击/拖动切换版本。
- **FR-030**: 刻度条必须支持按时间顺序自动播放与暂停，加载慢时等待而非跳帧。

**守护与降级（全程）**

- **FR-031**: 隔离（quarantined_visual）版本在所有入口（时间线、对比、快照、刻度条）必须带警示标识。
- **FR-032**: 未发布（非 published 生命周期）版本默认不得作为快照/对比目标，除非用户显式开启诊断模式。
- **FR-033**: 所有版本数据请求失败必须给出可理解的中文错误提示与重试入口。
- **FR-034**: 版本切换过程中的进行中请求必须可取消/防竞态，避免旧响应覆盖新状态。
- **FR-035**: 历史快照模式与差异模式不得修改任何源模型数据、DTX 数据或测量记录（纯只读功能）。

### Key Entities

- **发布版本（Release）**: 后端登记的模型发布记录，含 release_id、标签、branch_id、dbnum、注册时间、工作流生命周期与质量态双轴状态、相对差异摘要。时间线主刻度。
- **会话锚点（Anchor）**: 设计会话粒度的固化历史入口（dbnum + sesno），是会话级历史查询的唯一合法入口。时间线细刻度。
- **版本时间线节点**: 时间线上的一个可视节点（发布版本或锚点），承载状态徽章与操作（查看树 / 设为 A / 设为 B / 3D 加载）。
- **版本对（Compare Pair）**: 用户钉选的 A、B 两个版本及其可比性检查结论，驱动树内差异、双树对比与 3D 分色渲染。
- **历史快照模式（Snapshot Mode）**: 会话级只读状态：当前查看版本、只读横幅、被禁用的写操作集合、缓存键。
- **树差异条目（Tree Diff Entry）**: 单个元素的差异描述（refno、类别、增/删/改、before/after 存在性、属性差异懒加载句柄），驱动徽章与幽灵节点。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户从打开时间线面板到定位任一目标版本并看到其差异摘要，不超过 3 次交互。
- **SC-002**: 时间线面板首屏（≤50 个版本）加载在正常网络下 2 秒内完成；差异摘要懒加载不阻塞卡片列表滚动。
- **SC-003**: 在含已知差异的验证数据集上，树内徽章与后端 diff 结果 100% 一致（增/删/改类别与数量）。
- **SC-004**: 5000 条差异应用到树后，滚动与展开操作无可感知卡顿（交互响应 < 200ms）。
- **SC-005**: 历史快照模式下 100% 的写操作入口被禁用或拦截；退出后树与最新版本完全一致。
- **SC-006**: 二次进入已看过的历史版本时树呈现时间 < 500ms（缓存命中）。
- **SC-007**: 隔离/降级版本在时间线、对比、快照全部入口带警示标识（抽查覆盖率 100%）。
- **SC-008**: 历史过期与锚点缺失场景均给出可理解提示与可执行的降级选项（人工验收通过）。

## Assumptions

- 版本数据（发布版本、锚点、diff、快照）全部来自现有后端只读接口；本 feature 不新增后端写路径，不改动版本登记流程。
- 会话级历史入口遵守"锚点是唯一业务入口"约束；发布版本粒度不受保留窗口影响。
- 时间线为单库（项目 + dbnum）视角；多分支以筛选/分组呈现，v1 不做 git-graph 式分支绘图。
