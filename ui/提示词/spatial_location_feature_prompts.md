# 选择模型任一构件，计算其空间位置（楼层、房间号等）—— 专项提示词包

## 1. 功能定位

该功能的核心目标是：

> 用户在三维场景中选择任意一个模型构件，系统自动解析该构件所在的空间位置，并展示包括但不限于：
- 所属楼栋
- 所属楼层
- 所属房间
- 房间编号
- 空间路径
- 空间类型
- 定位置信度或来源

这个功能不是简单的信息查询，而应作为后续这些动作的上游入口：
- 同空间构件筛选
- 按房间/楼层发起校审
- 空间树定位
- 自动填充校审记录上下文
- 结果截图/留痕

## 3. 设计目标

请围绕以下目标做 UI 和功能方案：

1. 用户选中任意构件后，立即可看到它所在的空间位置
2. 结果必须足够清晰，不能只给一个 room id
3. 必须能解释“为什么这样判断”，至少给出来源或置信信息
4. 要兼容以下异常情况：
   - 构件不在任何房间内
   - 构件跨多个空间
   - 房间关系未计算或过期
   - 当前模型未加载完整
5. 定位结果不能只是展示，还要可继续操作：
   - 定位到房间树
   - 仅显示同空间对象
   - 按空间发起校审
   - 将楼层/房间号写入校审记录

---

## 4. 推荐页面形态

建议做成“轻量结果卡 + 可展开详情面板”模式。

### A. 三维场景
用户点击任意构件。

### B. 右侧详情面板 / 浮动结果卡
展示：
- 当前构件名称
- refno / dbnum
- 所属楼栋
- 所属楼层
- 所属房间名称
- 房间编号
- 空间完整路径
- 匹配方式 / 来源
- 置信度
- 结果状态

### C. 结果操作区
包含：
- [定位到房间树]
- [显示同空间构件]
- [按该空间发起校审]
- [复制空间路径]
- [刷新定位]
- [查看候选空间]

---

## 5. 推荐交互流程

## 流程 1：标准成功流程

### 步骤 1：用户选择一个构件
用户在三维中点击任意一个模型构件。

### 步骤 2：系统识别构件身份
系统拿到：
- refno
- dbnum
- AABB/中心点
- 模型版本或上下文

### 步骤 3：系统请求空间定位结果
调用后端空间定位接口，返回：
- 楼栋
- 楼层
- 房间
- 房间号
- 路径
- 来源
- 置信度

### 步骤 4：右侧展示空间定位结果
结果卡展示完整空间信息。

### 步骤 5：用户继续操作
用户可：
- 定位到空间树节点
- 显示同空间构件
- 发起校审
- 复制路径
- 重新识别

---

## 流程 2：构件不在任何房间内

用户选中一个构件后，系统无法匹配到房间。

UI 反馈：
- 显示“未匹配到空间位置”
- 展示可能原因：
  - 不在封闭房间内
  - 房间关系尚未计算
  - 构件数据缺失
- 提供操作：
  - [重新计算空间关系]
  - [查看邻近空间]
  - [仅显示所在楼层]

---

## 流程 3：构件匹配到多个候选空间

用户选中一个跨边界构件。

UI 反馈：
- 主结果显示“存在多个候选空间”
- 默认显示置信度最高的一项
- 可展开候选列表：
  - 房间 A
  - 房间 B
  - 走廊/公共区
- 用户可手动选定一个结果用于校审上下文

---

## 6. 推荐状态机

### 状态 A：未选择构件
- 右侧显示空状态
- 提示用户点击模型构件

### 状态 B：已选择构件，正在定位
- 显示 loading
- 禁用空间相关操作按钮
- 支持取消本次查询

### 状态 C：定位成功
- 展示完整空间结果
- 启用后续操作按钮

### 状态 D：未命中空间
- 显示未命中状态
- 展示原因和建议动作

### 状态 E：多候选空间
- 主结果 + 候选列表
- 可人工指定目标空间

### 状态 F：房间关系未就绪
- 显示系统状态异常
- 提供“重建空间关系”入口

## 8. 微文案建议

### 空状态
- 请选择一个模型构件以查看其空间位置
- 点击三维场景中的任意构件，系统将自动识别楼层与房间信息

### 加载中
- 正在解析构件所在空间…
- 正在匹配楼层与房间信息…

### 成功
- 已定位到该构件所在空间
- 已识别该构件的楼层与房间信息

### 未命中
- 当前构件未匹配到房间信息
- 该构件可能位于公共区域、室外区域或未建模空间中

### 多结果
- 检测到多个候选空间，请确认使用哪一个结果
- 当前构件位于空间边界附近，已优先显示最可能结果

### 系统未就绪
- 房间关系尚未建立，暂时无法定位构件空间
- 请先完成空间关系计算后再重试

## 15. 我对这个功能的最终建议

不要把这个功能做成“仅在属性面板里附带显示一个房间号”，而要做成一个独立的“空间定位能力入口”。

更好的产品定义是：

- 输入：一个被选中的构件
- 输出：一个可解释、可继续操作的空间上下文
- 中间能力：房间关系、空间树、当前选中上下文、异常降级
- 后续动作：同空间筛选、发起校审、记录留痕、空间树跳转

这样它才能成为后续：
- 空间模块化校审
- 同空间过滤
- 自动填充校审位置
- 管道/构件空间分类校审

这些功能的统一上游。
