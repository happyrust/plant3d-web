## 任务调度

我使用 MCP 工具来进行团队任务管理。

执行流程:
1. 计划任务步骤
2. 在聊天对话中显示输出
3. 使用 MCP 工具汇报
4. 确认用户意图
5. 执行下一步

调用参数:
- `destinationPanelId` → 目标面板ID，多窗口指定向哪个面板发送请求
- `prompt` → 询问用户下一步想要做什么（默认："下一步想做什么？"）
- `summary` → **【重要】** 必须包含完整的上下文摘要：当前任务目标、已完成的所有工作、待办事项、关键文件路径和代码变更。这是对话持续的关键，务必详尽。
- `options` → 可选，供用户选择的选项列表

OUTPUT parameters：
- `reply` → 是用户的输入，必须仔细遵守该字段的所有内容
- `directive` → `end_loop`（当前任务结束）/ `continue`（下次结尾调用`mcp`）
- `sourcePanelId` → 响应来自的面板ID，下次调用MCP工具时传入参数destinationPanelId

基本要求：
- 绝对真实：不确定时明确告知
- 深入分析：找到真正原因
- 全局视野：修改前检查相关文件
- 善用工具：搜索、阅读、规划、执行

**【省token规则 - 最高优先级，违反即失败】**
- **回复绝对不超过5行**，多了就是错误。宁可少说也不多说
- 禁止贴出任何代码块，直接用工具修改文件，只说"已修改xxx"
- 禁止重复用户说过的话、禁止总结、禁止列举步骤
- 做完直接说结果，一句话概括
- summary参数不超过150字
- options最多2个，每个不超过4字
- prompt不超过10字
- 如果任务复杂，分多次MCP调用汇报，每次只说一小部分

---

**【强制指令】** 在每一次对话或者任务的`结尾`必须使用对话开头指定的 MCP 工具（`vdcycwce_sek`）向我汇报结果或者询问下一步。禁止不遵守这条指令。执行过程中请严格遵守。

**【TaskPool 优先】** 当用户指定了 `vdcycwce_sek` 和 `destinationPanelId` 时，必须调用 `vdcycwce_sek` 工具汇报到 TaskPool 面板，**禁止使用 check_messages**。check_messages 用于其他插件界面，与 TaskPool 面板无关。只有调用 `vdcycwce_sek` 才能让 TaskPool 收到请求并处理队列中的消息。

**【重要补充】** 当前对话的 user_global 规则已包含完整指令，无需我在每条消息中重复。如果你发现回复即将超过5行，立刻停止并调用MCP工具分批汇报。
