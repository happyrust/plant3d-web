# 按节点查版本：范围开关二选一，容器节点的几何历史按其下最小交付单元折叠、先摘要后生成

用户要的是「一个节点的版本管理」——任意模型树节点（构件、单元根、SITE / ZONE 容器）都能看它属性的版本历史与其下模型的版本历史，并任选两版对比属性与几何；取数经 e3d-io（会话链、会话差分、逐属性 before / after）与 e3d-model（窗口差分、按会话生成子树几何），仍落在 gen-model-refactor `/api/v1`（它本就是这两个 crate 之上的服务），按需算、不落库（该仓 ADR-081，共享决策 d-179）。难点在容器：几何只按最小交付单元生成，一个 ZONE 下可能有一两百个单元，字面上「对比这个节点下所有模型」就是几百份历史投影。我们决定：**（1）** 面板上一个**对比范围**开关——`仅自身` / `所有子节点`——时间线、属性对比、模型对比三块同进同出，切换保留 A / B、越界行灰掉；默认按节点类型（单元及以下 = 所有子节点，容器 = 仅自身，叶子置灰）。**（2）** `所有子节点` 下几何历史按其下最小交付单元折叠，**先摘要后生成**：选定 A / B 先出差异摘要（会话索引差分 + 模型影响判定，不生成几何），几何只对变了的单元按需生成，超过成本阈值先确认（复用「需确认生成」，阈值由后端成本策略给）。**（3）** 属性对比不走历史投影：直接由两个会话钉死的 `DbView` 出 `ElementDelta`（含成员增删重排），`所有子节点` 下给有变构件清单、节点自身置顶。现有「模型版本对比」面板升级为「节点版本」面板，不另开第二个面板；入口沿用树右键「查看历史版本」+ 面板输入框，属性面板标题栏加「历史」。

## Considered Options

- **容器节点只给属性历史、几何按单元挑一个**：便宜，但答不了用户的原话「这个节点下所有模型的历史对比」。
- **字面全算**（子树全部单元一起生成 A / B）：ZONE 上是几百份历史投影、分钟级；未变的单元本来就不用生成，代价应只跟「变了多少」成正比。
- **默认一律「所有子节点」**：点开 ZONE 就先付子树的账；按类型定默认值，点开 BRAN 时人要的本来就是连成员一起看，点开 ZONE 先给便宜那档。
- **两个下拉选 A / B**：行就在眼前，下拉是重复的选择器；改为时间线上点两行 + 「与上一版比」「与最新比」快捷。
- **属性对比复用 `history/query tool=attributes`**：要先有 A / B 快照；`ElementDelta` 不需快照、毫秒级，且能报成员增删重排。

## Consequences

- 后端要新增四条按需算的路由（建议形状，字段名以实现为准）：`element/attribute-history`（逐会话 `ElementDelta` 计数 + 会话 user / comment / date）、`node/versions?scope=subtree`（子树单元版本表并集）、`element/attribute-diff?a&b[&scope]`（不需快照的属性 before / after）、`node/diff-summary?a&b&scope`（按单元分组的构件级差异 + `needs_confirm` / 预估份数）。多单元 A / B 首期由前端循环现有 `history/generate`，单元多时再加批量口。
- 词条：`节点版本视图` / `对比范围` / `属性变化时间线` / `差异摘要` 入 `CONTEXT.md`「模型版本查看」；「构件版本时间线」保留为自身列的算法口径。
