# 模型树与三维几何改从 gen-model `/api/v1` 取数，经数据源端口切换、旧链路保留在开关后

模型树与三维模型两条数据链的取数点不再直接调旧后端（`plant-model-gen :3100` 的 `/api/e3d/*`、parquet / DuckDB-WASM、`/files/meshes/**.glb`），而是经四个数据源端口（`TreeSource / ModelRecordSource / MeshSource / AttributeSource`，`src/model-source/ports.ts`）取数；端口后面两个适配器：`legacy` 原样委托现有函数（零逻辑，`model_source=legacy` 下逐字节同前），`gen-model-v1` 走本仓 gen-model 的 `/api/v1`（`tree/*` + `search` + `model/ensure` + `model/records` + `element/attributes` + `/api/v1/meshes/{hash}.glb`）。一个页面只有一个几何数据源：开关 `?model_source=` → `VITE_MODEL_SOURCE` → 默认 `legacy`，切到 v1 时 `useDbnoInstancesDtxLoader` 把调用方的 `parquet` / `backend` 一律改写成 v1（自带不可变清单的版本对比调用除外）。默认在浏览器两源对拍通过之前**不翻**。

服务端配套只做加字段 / 加端点（gen-model P0）：`GET /api/v1/meshes/{geo_hash}.glb` 由服务端把 rkyv 归档的 `PlantMesh` 现场编成 GLB（内容寻址，`immutable` 缓存），前端复用既有 GLB 解析；树节点与 `search` 项带 `dbnum` / `noun`；`/dbnums` 带 `ref0s`。前端因此不解 rkyv（与 rkyv 0.7 / glam 内存布局强耦合，任何一边升级都静默读歪）、不改 DTX 的按 `dbnum` 分桶（缓存、可见性、选中都靠它），`ref0 → dbnum` 改从 `/dbnums ref0s` 建。gen-model 没有单一 WORL，前端合成一个虚拟根 `gm-root:<project>:<mdb>`，children 是全部 SITE；祖先链末尾补这个根，定位算法「从根向下逐层找」不依赖顺序。「显示一个节点」= `ensure(force=false)` → 逐生成根分页 `records` → `matrix = compose(world_trans) × compose(inst.transform)`，坐标 mm / Z-up 不换算（BRAN 24381/145018 对拍 22/22 记录 ≤ 0.002 mm 后才允许这句话成立）；容器 `422 container` 按契约展开一层，`generation_pending` / `timeout` 不重试同一 refno。

否决的备选：前端手解 rkyv（脆，见上）；gen-model 生成期旁写 `.glb`（磁盘翻倍、48k 历史网格要回填、耦合发布队列的持久边界）；就地改写 `genModelE3dApi.ts` / `useDbnoInstancesDtxLoader.ts` 而不加端口层（没有回退也没法并排对拍，且大量 `*.test.ts` 依赖旧签名）；把 `dbno` 退化成「项目一个桶」（触及 `cachesByDbno` 与十几个 `resolveDtx*ByRefno(dbno, …)` 调用点，改动面远大于服务端加一格 `dbnum`）；树根做成「项目 → 每库一个节点 → SITE」两层（勾选 / 过滤 / 定位处处要特判非 refno 节点）。
