# 测量拾取层对齐 E3D Positioning Control：拾取过滤器 × 拾取类型两维模型，Any 只放行 Element / Ppoint / Pline，Graphics 细节从已加载网格派生，Intersect 按 E3D 分型做两（三）次子拾取求交

测量取点（Measure Distance / Angle / Perpendicular to 共用）的「哪些东西能被拾中、拾中后落在哪里」不再是一排点源开关，而是 E3D 3.1 Positioning Control 的**两维拾取层**（2026-09-13，方案 `docs/plans/2026-09-12-e3d-measure-parity-plan.md` Phase A）：**拾取过滤器**（`EDGPOSCNTRL.loadPicks` `picks[1..8]`：Any · Element · Aid · Pline · Ppoint · Screen · Graphics · External，顺序、标签与 E3D 面板一字不差）× **拾取类型**（`pickTypes[1..7]`：Snap · Distance · Mid-Point · Fraction · Proportion · Intersect · Cursor），外加 **Significant Snaps**（`intermediate`）一档；缺省 Any × Snap × Significant Snaps 开（Measure 的 `stdPosition` 拾取就是 `Any`，`pickTypeIndex = 1`）。Web 已有的点源按 E3D 的特征类归位而不是并列：`ptset` → Ppoint、`position` / `primitive_key_point` → Element、PLINE 端点配成线 → Pline、`mesh_pick_point` → Screen（Web 表面点）、新增 `mesh_graphics` → Graphics；过滤器决定候选**准入**（`measurementPickFilterAdmits`），拾取类型决定拾中几何上**落点怎么派生**（`pickDerivation.ts`：点候选原样、线候选按近端 / 中点 / 等分 / 比例 / 走距离、面候选一律 射线 ∩ 平面），两维正交、互不知晓。提示条改成 `EDGSTATE.prompt()` 的结构 `<命令> · <步> (<拾取类型 token>) [Snap] : <目标>`（`距离测量 · 第 2/2 步 选择终点 (Mid-Point) Snap : ELBO P-Point #1`），过滤器**不进提示**、与 E3D 一致；拾取类型的取值（Distance mm / Fraction n / Proportion 0–1）与整个拾取层进测量样式仓 V9 持久化，未知或不可用的 id 回缺省。Aid / External 两档留在列表里灰掉并写明原因（Web 没有设计辅助系统，方案 §7 Q3 未拍板；外部几何不在本期），不从列表里删——用户看到的是 E3D 那张表。

三条具体口径是这条 ADR 要钉住的，因为每一条都有一个「更宽松、看起来更好用」的替代，而我们有意没选：

**（1）Any = Element / Ppoint / Pline（+ Web 表面点），不是「全部」。** `EDGPICK.stdAny` 的注释是「Standard pick interpreter for Element, Ppoint or Pline」（`inMode = 'pany'`），Graphics 细节要 `stdGraphics`（`inMode = 'pickdetail'`）、辅助要 `stdAid`、外部几何要 `stdExternal`——E3D 里 Any 从来不拾 facet 边 / 面。Web 照此：Any 放行 `element` / `ppoint` / `pline` / `surface`，**不放行** `graphics-line` / `graphics-plane` / `aid` / `external`；Graphics 边 / 面只在 Graphics 过滤器下参与，反过来 Graphics 过滤器下 P-Point / Item 原点一次都不出现（实机扫描 132 像素为证，golden MD §12）。表面点算进 Any 是 Web 的一处有意偏离：它是 E3D「附近没有显著点时拾元素本身」（自由表面态）与 `Element` × `Cursor`（`edgTypes.attribute(noun).exact()`，元素上的精确点）两种情形在 Web 的替身；`Element` 过滤器也只在 Cursor 类型下放行它，其它类型下 Element 就是显著点。被否决的替代：Any = 所有点源并集——一旦 Graphics 边进了缺省过滤器，12 px 内的网格棱会在整个模型上抢走 P-Point 的吸附（渲染细分的边处处都是），缺省体验反而变差，而且 E3D 也不是这么做的。

**（2）Graphics 过滤器从已加载网格派生，前端本地，不问后端。** E3D `pickdetail` 拾的是构件绘制细节：facet 边 → `3D_LINE`（`getLine()`）、facet → `PLANE`（`getPlane()`）。Web 没有 PDMS 图形核可问，gen-model 吐的是烘好的实体、没有逐 facet 细节，于是从 DTX 已经为渲染加载的三角网格派生（`src/measurement/graphics/meshFeatureGraphics.ts`，纯函数、无 three.js 依赖）：**绘制边** = 边界边（只有一个邻接三角形）/ 非流形边（≥ 3 个）/ 二面角 ≥ 30° 的边，度 2 顶点处的共线段合并成一条——盒棱是一条线、圆柱端面圆周仍是一圈短边、圆柱母线在粗细分（8 段，二面角 45°）下是线、细细分（36 段，10°）下消失，这正是 E3D 绘制边的粒度；**面** = 命中三角形所在平面，并 BFS 出边连通的共面片给高亮轮廓（盒面一整片，圆柱侧面一格）。命中规则：光标射线 12 px 内有绘制边 → 边候选（控制点 = 边上离射线最近处，带 `segment` + `direction` 供拾取类型内核与 Perpendicular 轴线用），否则一个面候选（控制点 = 命中点，带 `plane` + `outline`）；同屏幕位置的边只留离相机最近的一条（正视盒体时背面棱不抢前面棱）。派生结果按 objectId + 世界矩阵缓存。这样拾出的点标 `近似`（`model-surface` / approximate）：网格是渲染细分不是设计曲面，圆柱面上的「面」是一格平面。Perpendicular to 顺带得到 `facet-plane` provider（E3D `getPlane()` 分支，文案「所在平面」）。被否决的替代：服务端新开 `pickdetail` 端点（要 e3d-model 逐基本体吐 facet 拓扑，是 Phase A 最大的后端工作量且与 `element/keypoints` 抢同一份放置矩阵改造，见 §7 Q5；而绘制边从网格就能确定地算出来）；直接把渲染三角形的每条边当线（细分边处处可吸，无法区分棱与曲面）；屏幕空间做二维边缘检测（随相机变、无三维几何可给 Perpendicular / Intersect 用）。

**（3）Intersect 按 E3D 分型做两（三）次子拾取，交点是一个 POSITION。** 逐条对照 `EDGPICKTYPE.intersect`（`edgpicktype.pmlobj` 616–960）与 `EDGSTATE.minor`：每次子拾取先转操作数——带段的（Graphics 边 / PLINE / `3D_LINE`）→ LINE，带面的（facet / Aid 平面）→ PLANE，带方向的点（P-Point / 基本体轴，E3D 的 PPOINT / DPOINT / PIN）→ POINTVECTOR 线，**裸点 → 拒收且不消耗这一击**（E3D「Unable to convert item into a line or plane for intersection」）；首项入栈，提示 token 推到 `Intersection[2]`；两项即求交，**两面要第三项**（`golabel /nextPick`，`Intersection[3]`）；线 × 线 / 线 × 面平行 → E3D `(2,870)`，**只丢失败的那一击、首项保留**；三面无唯一交点 → `(2,874)`，**整个会话清空**（`numberOfPicks = 1`）；异面直线不算错，取第一条线上离第二条最近的点（`LINE.intersection` 的口径）。交点作为这一击的测量点进正常流程时 label「交点」、几何字段清空——E3D 回的是 POSITION，所以 Mid-Point / Fraction 这些线上派生不会再链到交点上；Esc 分层多出第一档「先放弃进行中的子拾取」；换拾取类型 / 过滤器、重新激活都重置会话；已有子拾取时悬停用当前项试算交点做预览（「交点（预览）」）。ARC 操作数（E3D 的弧 × 线）Web 暂无，拒收不消耗。状态机是纯函数 `src/measurement/kernel/intersectPickSession.ts`，12 条单测覆盖分型、序号、两种错误码与清空规则。被否决的替代：「任意两次拾取取最近点对」（不是 E3D 的语义，面 × 面会回一条线而不是点）；一律两击（E3D 两面需第三项，少一击就没有唯一解）；任何失败都清空（E3D 只在三面失败时清空，平行时保留首项让用户换一条线即可）；把交点当带几何的线候选继续派生（E3D 回 POSITION）。

**证据等级**：以上规则全部是 `static_expectation`——出自 E3D 3.1 PMLLIB `edgposcntrl.pmlobj` / `edgpick.pmlobj` / `edgpicktype.pmlobj` / `edgstate.pmlobj` 的源码阅读，**不是**运行时观测；G7-02（EDGE / PLANE 实际捕捉几何）、G8（拾取类型位置字串、Intersect 交点）、G9（Element 显著点）三组 E3D 运行时 golden 都还未采（E3D 进程不在跑）。任何一条与 golden 对不上时改 Web、改这条 ADR 的措辞，不改 golden。

不做的：不建 Aid 系统、不做 External（列表里灰掉，§7 Q3 另议）；不做服务端 `pickdetail`；`element/keypoints`（Element 显著点按 noun 的 `edgTypes`：盒角 / 面中心 / 圆柱轴端）与 `element/plines` 服务端、TUBING 轴线点前端派生不在本条范围（Phase A 未完清单）；Positioning Control 的 Offset / Working plane / grids 是定位能力，不进测量。
