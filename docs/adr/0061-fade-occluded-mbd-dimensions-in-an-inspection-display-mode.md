# 尺寸系统增加 inspection 显示模式：被模型挡住的整条尺寸淡化、其余稍淡，不隐藏（混合因子 0.80 / 0.92，上屏约 35 % / 65 % 对比；2026-09-14 从 0.35 / 0.65 重定）；默认 engineering 全画；遮挡由宿主对每条记录的探测点做一次相机射线求交判定

尺寸视口多一个显示模式 `DimensionDisplayMode = 'engineering' | 'inspection'`（`DimensionViewport.setDisplayMode`，默认 `engineering`，2026-09-13）。`engineering` 与本条之前完全一致：每条尺寸、标签在模型之上全画（工程 overlay 约定不变；2026-09-14 起描边改写近平面常量深度、只对自身去重，对模型仍是全画，ADR 0062），轴测图阅读优先。`inspection` 给校审场景用：每次**完整布局**结束后（成对去重、标签 billboard 放置、移动式避让都做完，每条记录的几何已定），内核对每条**画出来的**记录取一个探测点——第一条字形的三维锚点，即长度尺寸的数值文字基线中心（标签 billboard 的取法见下段）；没有字形才取第一条描边的顶点——从该点像素在近平面上的反投影点向探测点发一条线段，问宿主「可见模型几何有没有在这条线段上、比探测点近至少 ε」；答是的记录写 `derived.occluded = true`，否则 `false`（`kernel/layout/occlusionPolicy.ts::markOcclusion`）。画家按记录整体着 α：`inspection` 下被遮挡 `theme.inspection.occludedAlpha`、可见 `visibleAlpha`（两态可分，且被遮挡的仍读得出——背面尺寸在校审时也要能对；数值见下面「α 重定」段）；`engineering` 下 α = 1 且描边实心遍、实心箭头、标签填充三种材质保持不透明（`transparent=false`；描边的羽化边缘那一遍是部分覆盖，始终混合，ADR 0062），不做任何探测。α 是逐顶点属性 `batchAlpha`（描边 quad、实心箭头、标签填充三套缓冲各一份），`updateStyles` 换色时一并重写，hover / selected 不会把淡化冲掉。inspection 下同一记录相邻描边重叠处（字形接头、尺寸线压尺寸界线）经深度去重只着色一次，淡化是均匀的（ADR 0062）。

**标签 billboard 探锚点，但把它点名的构件从遮挡体里去掉；点不出构件的标签才探卡片**（2026-09-13 实机对照后两轮修正，用户 22:15 拍板）：标签的锚点就在它点名的构件上或构件里（阀门原点、弯头角点、连接处的管口中心），向锚点发射线从任何方向都会先打到那个构件自己——BRAN 24381_145018 实机第一轮里阀门位号 `Copy-of-1RCS002VP` 与几张坐标卡片正面、背面都被标遮挡，而卡片明明浮在空白处；ε 吸收得了「锚点恰在管面上」的浮点差，吸收不了半个构件。第二轮（提交 `9de9e60`）曾把标签一律改探卡片屏幕中心在锚点深度上的反投影点，卡片不再误标，但这一取法下标签几乎永远不淡（ADR 0059 的放置本来就让卡片避开可见构件的凸包），而校审要的是「**被点名的构件本身**被别的几何挡住时标签淡」。所以最终口径：plant-mbd 的标签 id 带着它点名的构件 refno（`…:tag:elbo:<refno>` 弯头、`…:tag:name:<refno>` 位号、`…:tag:connection:<refno>` 构件处的坐标卡片），`mbdV2ExternalAnnotations.ts::classifyTag` 把它读成 `ExplicitTagInput.subject`，`planTagBillboard` 随布局落到 `derived.tag.subject`；`occlusionProbe` 对带 `subject` 的标签仍探**锚点**，但把 `subject` 装进 `OcclusionProbeHints` 随射线交给宿主缝。DTX 适配器在这条射线上跳过两类命中：`subject` 自己的各个 piece（DTX 对象 id 是 `o:<refno>:<n>`，一个构件可能装成几块，`refnoOfDtxObject` 取中段比对），以及**包着锚点的体**——从锚点前 ε 处沿视向再发一条射线还能穿出去的对象（图层的三角求交是双面的，出口壁算命中；ε 起步让锚点恰在其端面上的体也算进去）——连接卡片处管子与管件相接、阀门原点在阀体内都靠这一条；其余命中比锚点近 ε 以上才算遮挡。没有 refno 的标签（`connection:Head` / `connection:Tail` 两张端点卡片：锚点是管口中心，点名的是「这一端」而不是某个构件；`branch-name`）没有可排除的构件，退回探**卡片**：卡片屏幕中心在锚点深度上的反投影点，问的是「有没有比锚点更近的几何画在卡片所在的位置」。尺寸（数值文字站在管外）不变。`subject` 对内核不透明，只是一个从适配器经布局传到宿主的字串；别的 producer 的标签没有它，就走卡片那一档。实机（BRAN 24381_145018，背面相机）：阀门 `24381_145035` 的原点被直管 piece `o:24381_145018:5` 挡住（命中比锚点近 3.0 m），位号 `Copy-of-1RCS002VP` 淡到 0.35；正面与阀门簇中景射线上只有阀门自己的 piece，位号 0.65；连接卡片 `X 9201`（`24381_145032`）三个相机都只打到它自己的 piece，0.65。ELBO 近景补验（9 弯头 × 14 方向，124 个画出标签的视图）：弯头自己的 piece 挡在锚点前的 46 个视图里，没有别的几何的 26 个标签保持 0.65、另有别的 piece 挡着的 20 个淡到 0.35，独立射线复核 124/124 与内核一致，「包着锚点的体」在 ELBO 上为 0。

**α 重定（2026-09-14，用户拍板「往上调，让淡化后看起来和数字一致」）**：2026-09-13 定的 0.65 / 0.35 是照 2D 画布的直觉给的，但画家的 α 是**线性光里的混合因子**，混合结果再经 DtxViewer 的 ACES 色调映射（曝光 1.3）与 sRGB 编码才上屏，深色文字（线性 ≈ 0.005）压在浅背景（线性 ≈ 0.8）上时，混合后的线性值被曲线的亮部拉得很浅：实机（RX590，2× DPR，OutlinePass 路径）量卡片 / 三维数字 / 药丸文字对背景的显示空间对比，0.65 只呈现约 **20 %**、0.35 约 **8 %**（`inspection-alpha-sweep.json`：α → 呈现对比 1.0→100 %、0.96→78 %、0.94→70 %、0.92→63 %、0.90→57 %、0.85→45 %、0.82→40 %、0.80→36 %、0.78→34 %、0.75→30 %、0.65→20 %、0.50→12 %、0.35→8 %）。按「可见 ≈ 65 %、被遮挡 ≈ 35 %」反查：`visibleAlpha` **0.92**、`occludedAlpha` **0.80**。图纸红的尺寸线（中间调）在同一 α 下保留得更多（0.92 → 78 %、0.80 → 58 %），几何比文字更耐淡，可接受。两态在文字上差 27 个百分点、在线上差 20 个百分点，仍可分。不改混合方式（改成在 sRGB 空间混合要把整条 overlay 挪出 composer 的线性目标，不值）。

ε = max(`toleranceMm` 0.5 mm, `tolerancePx` 2 px × 探测点处的 worldPerPixel)：标签锚点本来就在管面上，射线打到它所在的那一面时命中距离与探测点距离只差浮点噪声，不能算遮挡；2 px 那一档让远景不因像素级抖动翻转。射线从**近平面**而不是相机位置出发：近平面前的几何渲染器本来就裁掉了，不该当遮挡体。粒度是整条记录：一条尺寸要么整条淡、要么整条亮，不按图元拆——数值、尺寸线、箭头、尺寸界线分开淡化会把一条尺寸读成两条。

宿主缝是 `DimensionViewerAdapter.isSegmentBlocked?(from, to, toleranceM, hints?)`（设计空间米；`hints.subject` 见上段；可选，没有它 inspection 只是把所有记录画成 0.65），facade 包成 `OcclusionSource` 交给 `DimensionViewport`，随 `displayMode` 一起进 `layoutViewport` 的 options。DTX 适配器用已有的 `getDtxLayer` 实现：线段两端经 designToWorld 到场景世界，`DTXLayer.collectObjectBoundsIntersecting(线段包围盒, { visibleOnly: true })` 取候选构件，逐个 `DTXLayer.raycastObject(objectId, origin, direction)`（图层自己乘全局矩阵、隐藏对象返回空、先做对象包围盒预检再逐三角求交），第一个命中距离 < 线段长 − ε（ε 按同一线段的设计 / 世界长度比换算）即阻挡——带 `subject` 时先跳过该构件自己的 piece，再对每个够近的命中补一条「从锚点前 ε 处向前」的射线，穿得出去的是包着锚点的体，也不算。这是**真实网格**的求交（不是包围盒），所以判定对渲染出来的模型是精确的，同一相机 / 同一模型状态下结果逐条相同（探针实测两次布局与宿主帧循环签名一致）。

入口在尺寸面板「MBD 图元类别」块下的「显示模式」单选（Engineering（工程）/ Inspection（检视：被模型挡住的尺寸淡化）），状态记在 URL `mbd_mode=inspection` 上，但**不派发 `popstate`**：模式只关系呈现，直接调 `viewport.setDisplayMode`，不像 `mbd_kinds` / `mbd_lod` / `mbd_3d` 那样让同步层重拉一次 payload（实测切换时 payload 请求数不变）。浏览器前进 / 后退带来的 `popstate` 仍会把 URL 里的模式同步回面板与视口；视口被重建时面板按 URL 校准。检视模式下面板显示「被遮挡 N 条 / 可见 M 条」（只数画出来的 MBD 记录）。

不做的：不读深度缓冲（overlay 与模型 pass 的深度目标 / MSAA 不可控，且 GPU 回读破坏确定性）；不用包围盒判遮挡（弯头 / 阀门误判多，ADR 0059 的凸包只用于标签放置）；不隐藏被遮挡尺寸（校审要看背面）；不按图元淡化；不改布局几何、不搬动任何记录；不改契约、不改求解器；2k 记录的分帧预算暂不做——每条画出来的记录一次射线，候选构件先按线段包围盒筛，本样本 23 条记录一帧内完成。

被否决的替代：直接对模型开启 `depthTest`（尺寸会被管体吃掉，工程 overlay 约定就没了；ADR 0062 的深度测试只对描边自身去重，对模型仍恒通过）；对整条尺寸线采样多点求交再投票（成本 × N，且中段被挡、两端露出时读数仍在，粒度反而更糊）；把模式做成两套主题（α 不是颜色，engineering 的材质本该保持不透明；模式与主题正交，切模式不该换色）；模式走 `popstate` 重同步（多拉一次 payload、闪一下，只为一个呈现开关）；把遮挡判定放进画家（画家没有布局后的探测点，也不该持有宿主射线缝）。
