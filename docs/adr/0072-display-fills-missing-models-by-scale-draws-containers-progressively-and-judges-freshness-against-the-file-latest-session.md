# 显示查空时按规模补齐模型，容器边取边画，新旧按库文件最新会话判

ADR 0069 把「显示」定成只查询：点眼睛不生成，查空就提示人去右键。用下来有三处不够。其一，用户要的是「这个 SITE / ZONE 没生成过就先生成再加载」，
0069 的 2026-10-14 追记只对 BRAN / HANG / SUPPO / EQUI 自动生成，工作区里已经放宽到任何节点，但没有规模上的约束，发出去的还是先删后生成（`force: true`），
查空之后要等一次整库根枚举才决定生不生成（实测 24–30 秒）。其二，容器要等全部记录、全部网格到齐才画第一帧（7400 件 2.1 秒，8 万件 11.5 秒），
期间还盖着一层整屏遮罩。其三，「是不是最新」各处说法不一：模型树的库状态圆点只比模型与已入库的数据，库文件多出 10、23、8 个会话的三个库都显示「最新」，
而「模型生成」面板对同样的库说「待更新」；节点一级没有新旧可言。2026-11-10 用户就这几件事定了下面六条
（方案与取舍的全文在 `docs/plans/2026-11-10-model-load-speed-generate-and-freshness-plan.md` 第 6 节）：

**（1）显示仍然先查询，查空时补齐。** 只有「记录查询成功、收齐、确实一条都没有」才对这个节点做模型资产补齐，补齐发的是不带 `force` 的
`POST /model/generate { refno }`——后端只生成缺的和落后的根，已有的原样返回。记录查询失败、没收齐（409、出错、预算外）、退到子树查询、或者 `/dbnums` 说这个库的模型
正在追平已入库的数据（`model_lagging`）、库正在被写（`initialization_publishing`）时，一律不补齐，只给提示。`force: true` 只留给右键「重新生成模型」和「模型生成」面板。
库里有没有模型看已经缓存着的 `/dbnums` 那一行，显示路径和状态圆点都不再调 `dbnums/{库}/model/roots`。

**（2）补齐按规模分流。** 生成单元不超过 20 个的直接生成并显示；超过的先确认一次，写明有多少个单元没有模型，可以选「只显示已有的」；
确认后按 ZONE 分块生成，做完一块显示一块，带进度。阈值由后端的生成预检给出，预检接口没上之前前端按同一个数过渡。

**（3）容器边取边画。** 按成员拆开查的节点（顶层 SITE 按它的 ZONE），每收完一个成员就把这一批装进场景，不等整个节点收齐：第一批立刻装，
之后攒够不少于已装的数量、或离上一批够久再装。相机在第一批到的时候飞一次，收齐后再对整体对一次焦，除非用户在这期间自己动过视口。
读记录期间不盖整屏遮罩，进度走查看器左下角的状态条；整屏遮罩只留给生成阶段。全部收齐才记为已加载。

**（4）「最新」按库文件最新会话算。** 库一级比三枚水位（库文件最新会话、数据入库到哪、模型按哪个会话生成）：三者对齐才是最新；
模型与数据一致但库文件还有新会话的，写「库有 N 个新会话未更新」，措辞保持中性——E3D 每次登录都会多一个会话，多数新会话没有改到几何。
SITE / ZONE 一级只在「模型生成之后的会话真改到了它下面的构件」（网格变、位置变、新增、删除）时才标落后，登录产生的空会话不算。
模型树的圆点和「模型生成」面板的徽标用同一个判定函数。

**（5）落后时先显示已有的。** 行上标出落后和原因，提供「更新到最新」；更新完成后出更新提示，人点「重载」才换场景（沿用 2026-10-26 的决定，不自动换）。
能看模型的人都可以点「更新到最新」；整库重排、清理这类重操作仍只放在「模型生成」面板里。

**（6）不为生成标记建新表。** 节点的状态由库水位、会话链、后端进程内的生成记录按需算出来（与 gen-model ADR-079「模型水位是唯一的持久模型事实」一致）；
页面里只记「装的时候是哪一版」。未初始化的库按需生成的结果只在后端内存里，后端重启就要重新生成，这一点不变。

性能目标（本机、冷态、三次取中位数）：大 ZONE 0.7 秒出图；整 SITE 0.7 秒出图、1.5 秒画完；8 万件 1 秒出图、6 秒画完；没生成过的小 ZONE 1.5 秒以内。

## Considered Options

- **查空时全自动生成，不分规模**（当时工作区里的做法）：小节点一点就出，但大节点一点就占用后端几分钟，没有进度，不能取消，误点了也在算。
- **查空时一律先确认**：几十件的 ZONE 也要点确认，烦。
- **落后就自动更新，更新完再显示**：看到的一定是最新，但把「看」变成了「改」，每次显示都可能等一个批次，任何人打开页面都会让后端开工；
  对库水位落后的库，后端会把节点下每个根整根重算。
- **更新完成后自动重载**：少点一次，但场景会自己变，要判断用户是不是正在测量或批注，判断错了会打断人。留作以后可选的第二步。
- **「最新」取数据水位**（原来圆点的口径）：界面简单，但库文件比入库的新时仍说最新，不在自动更新范围里的库永远是「最新」。
- **模型水位等于库文件最新才算最新，不看节点**：实现最简单，但 E3D 每登录一次，所有库的所有节点都变「落后」，等于没有信息（gen-model #65 的教训）。
- **后端新建一张 SITE / ZONE 标记表**：重启后还知道哪些节点生成过，但与 gen-model ADR-079 相反，每次生成多写一笔，回退、清库多一张表要管，
  和水位变成两套可能打架的事实。
- **容器维持全部到齐再画**：画面一次成型不会跳，但大节点要对着空白等十几秒。
- **边取边画按固定间隔（0.5 秒）装一批**：大场景装一批要几百毫秒，固定间隔会让装载占满主线程、拖慢取数；改成翻倍，按时间触发的间隔不短于上一批耗时的 6 倍。
- **边取边画按记录页交批次**：一个构件的记录可能跨页（BRAN 的直段记录都挂在 BRAN 自己的 refno 上），按页进缓存会互相覆盖。只按成员交，单个很大的 ZONE 不边取边画。

## Consequences

- 2026-11-10 落地的是 A1（查空不等整库根枚举）、B1（补齐不带 `force`、读失败不补齐）、A2（装载路径两处白耗）、C1（库一级新旧）、A3（边取边画）。
  2026-11-11 落地的是（2）的预检、确认框、分块生成与进度（B3）；（4）里 SITE / ZONE 一级的新旧和页面内的已加载节点表（C2）；
  （5）的「更新到最新」（C3，只验到单测和假接口，没有对正式后端调过 `update/execute`）；网格打包取的前端一半（A4，后端没部署时自动退回逐个取）。
  **还没有的**：后端的节点模型状态与生成预检接口（S1，`GET node/model-status`）没部署，下面三处是过渡办法，各只有一个换接口的入口——
  - 生成预检（`generationFill.planModelGeneration`）沿树往下数两层，数出来的是估计（界面上写「约 N 个单元」）；
  - 节点新旧（`nodeModelStatus.resolveNodeModelStatus`）用 `/dbnums` 那一行加一次 `node/versions?since_sesno=`，未初始化的库说不出新旧；
  - 「这个节点下哪一块没有模型」只能说到「哪个 ZONE 一条记录都没有」。所以**节点已有一部分模型时，只对模型按需生成的库（未初始化 / 模型水位没立过）
    补没有记录的 ZONE**；库里有成套模型时，没有记录的 ZONE 多半本来就没有几何或是模型水位之后才建的，不去生成。整个节点都查空时照旧会补。
- （2）落地时的两点取舍：
  - 确认框按场合给两个选项，不是三个并列。节点已有一部分模型时，已有的在问之前就已经显示出来了，选项是「生成并显示 / 只显示已有的」；
    一个模型都没有时是「生成并显示 / 取消」。没生成的部分记在页面里，行上给一个「生成」可以再来（已加载的节点再点眼睛只是恢复可见，不会再问）。
  - 分块生成回 504（后端 120 秒没算完）、409、503 或回执里有可重试的失败根时，隔 3、5、8 秒、之后每次 10 秒用同样的请求再问，一块最多等 10 分钟，
    不要人再点；不可重试的失败根在结束时点名，其余照常显示。生成跑过了没有可显示的东西、或有不可重试的失败的范围，本页面里不再自动重发；
    **超时的不算试过**，下次点眼睛接着问（原来是试过一次就不再发）。补齐期间进度走状态条，不弹整屏遮罩。
- （5）落地时：「更新到最新」发的是库一级的 `POST update/execute { dbnums: [库] }`，和「模型生成」面板是同一条路、同一张任务表；它更新的是整个库
  还没入库的会话，不只这个节点，点之前的确认框里写明。做完不换场景：重拉库状态，已加载节点表把真被改到的节点标成「有更新可重载」。
- `useModelGeneration.showModelByRefno`：查空分支按（1）收紧；`startProgressiveLoad` 订阅记录源的成员批次（`subscribeMemberRecords`），节奏在
  `progressiveLoadPolicy.ts`；收尾只装还没装的。`modelRecordSource` / `modelRecords` 多了成员批次的出口，显示路径仍然不出现 `generate`（源码钉 `display_never_generates` 照旧）。
- `src/composables/dbnumFreshness.ts` 是库一级新旧的唯一判定：`useGenModelV1DbnumStatus`（圆点）与 `useModelGenerationAdmin`（面板徽标）都只调它。
  圆点多了两种画法：蓝色是「库文件还有新会话」，转圈是「库正在被写」。
- **行为变化**：没生成过的节点点眼睛会生成（0069 是只提示）；一次读失败不再可能触发先删后生成；读记录期间不再有整屏遮罩，模型一块块长出来；
  模型与数据一致、库文件有新会话的库，圆点从绿色的「最新」变成蓝色的「库有 N 个新会话未更新」。
- 面板判「进行中」原来比的是 `write_state.status === 'running'`，而后端写的是 `writing` / `finished`，这个徽标一直亮不起来；统一判定里认 `writing`。
- 2026-11-11 新增的部件：`generationFill.ts`（预检与分块执行，纯逻辑）、`generationFillState.ts`（还没补齐的节点、正在补齐的节点、「停」的入口）、
  `nodeModelStatus.ts`（节点新旧的判定）、`useLoadedNodeStatus.ts`（已加载节点表）、`updateToLatestState.ts` / `useUpdateToLatest.ts`（更新到最新）、
  `model-source/genModelV1/meshBatch.ts`（网格打包取）。模型树的行上最多有三个小按钮：「生成」（下面还有没模型的部分）、「更新」（落后）、「重载」（有更新可重载）。
- **已知的缺口**：
  - 加载中取消没有按钮（要不要做在问用户）。入口已经留好：分块生成在块与块之间、每次自动再问之前都问一次「还要不要继续」，
    `requestStopGenerationFill(节点)` 置上标记就停；这个节点被隐藏了也会停。已经发出去的那一块后端照常算完。读记录、取网格阶段仍然不能停。
  - 「模型生成」面板拿的是带身份参数的 `/dbnums`，圆点拿的是轻量形态。被排除在自动更新范围之外的库，前者标 `excluded`（徽标「不参与」）且 `file_latest_sesno`
    是旧的观察值，后者不带 `excluded`、`file_latest_sesno` 是真的——同一个库在两处的数字会不一样（本机 1112：739 对 748）。这要后端把两种形态对齐
    （2026-11-11 已交给后端）。前端这一半已经做了：「不参与」「阻断」的库，徽标和提示在状态之外写出库文件还有几个新会话没入库（水位有就写，没有就不写）。
  - 重载（`replaceExistingObjects`）对旧对象是隐藏、不是释放：同一个节点每重载一次，图层里的对象槽多出一份。行上有了「重载」之后这条路会常走，要另开一片改成回收。
  - 「更新到最新」只对已初始化的库有；未初始化的库说不出落后，行上不会出现「更新」。页面刷新后「更新中」的状态不保留（后端的任务照常跑）。
  - 整库显示（`show_dbnum`）的整屏遮罩没有动。
  - SITE 正在边取边画时又去显示它下面的某个 ZONE，两路可能同时装同一批构件；装载器对「已装」的判断不是并发安全的。同一个节点的两路已经挡住，父子节点之间没有。
