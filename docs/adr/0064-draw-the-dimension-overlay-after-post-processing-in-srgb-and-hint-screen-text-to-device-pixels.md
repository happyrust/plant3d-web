# 尺寸叠层在整帧（含后处理）之后单独一遍画进 sRGB 画布：颜色按 sRGB 写、不过色调映射与 FXAA、羽化边按 sRGB 混合；屏幕文字对齐设备像素格（笔画取整到设备像素、最少 2 个，横竖笔吸到像素边界）

尺寸叠层（`viewport/scenePainter.ts` 的四个绘制对象：标签体填充、描边实心遍、描边羽化遍、箭头）此前挂在宿主主场景里、与模型同一帧画出。2026-09-14 实机量出这条路上文字被三样东西一起碾了：选中构件（`show_refno`）时整帧走 EffectComposer（RenderPass → OutlinePass → **FXAA** → OutputPass），FXAA 按亮度边沿把 1–2 像素的笔画抹糊；叠层的羽化边在 HalfFloat **线性光**里混合，深色文字 50 % 覆盖的边像素落在亮度 ≈ 166 而不是 sRGB 混合的 ≈ 125（ADR 0061 量过的「α 0.65 看起来像 0.2」同一件事）；OutputPass 再把叠层的**平色**过一遍 ACES（曝光 1.3），白卡片成 ≈ 240 的米白、深色文字被抬。没选中时走直接 `renderer.render`，画家的 ShaderMaterial 把 `new Color(hex)` 的线性分量原样写进 sRGB 画布（没有 colorspace 转换），`#334155` 落成 (8, 15, 26) 近黑——同一个叠层在两条路径上颜色不一样。1× DPR 无头 Chrome 的药丸 `PE +3212`（目标 `#334155`，亮度 62）133 个文字像素里中位亮度 **175**，只有零星像素到 63：1.8 px 笔画、1 px 羽化的实心核只有 w/2 − f/2 = 0.4 px 宽，几乎每个像素都是「边」。

**决定一：叠层自己一个 `Scene`，在整帧之后单独一遍画到屏幕。** `DimensionViewport` 拥有 `overlayScene`（画家的 group 挂在这里，不再进宿主场景；`DimensionViewerAdapter.getScene` 删除），并提供 `renderOverlay(renderer, camera)`：`autoClear = false`、只 `clearDepth()`、`renderer.render(overlayScene, camera)`、还原 `autoClear`。宿主（`ViewerPanel.vue`）在每处画完主场景之后调它——直接路径、OutlinePass composer 路径、双视口对比的每个 pass——都在 gizmo 之前。叠层因此不进 FXAA、不进 OutputPass 的色调映射；只清深度是因为描边两遍靠深度缓冲对自身去重（ADR 0062），而对模型本来就恒通过（写近平面常量深度），不需要模型的深度。画家的颜色改为 **sRGB 编码分量**（`Color.getRGB(target, SRGBColorSpace)`，`srgbComponents`）：片元着色器的输出就是上屏值，两条路径一致；羽化边与 inspection 淡化都在 sRGB 里混合。

**决定二：屏幕文字（billboard 标签文字、视平面尺寸数字）对齐设备像素格。** 画家给描边顶点多一个 `pixelSnap` 属性，屏幕空间字形段置 1，其余（尺寸线、引线、边框、标记、三维 framed 文字及其白边）置 0。(a) 笔画宽：`hintedTextStrokeWidthPx(theme.textStrokeWidthPx, dpr)` = max(2, round(w · dpr)) / dpr——1.8 px 在 1× 是 2 个设备像素、2× 是 4 个、1.5× 是 3 个；少于 2 个设备像素的羽化笔画没有实心核，这是 1× 上文字发灰的直接原因。(b) 位置：顶点着色器里 `pixelSnap` 段把两端投到设备像素坐标，**横竖笔**（两端某一坐标之差 < 0.01 设备像素，LFF 字形的直笔精确对齐坐标轴，斜笔与曲线不动）的那一坐标吸到格上——偶数宽吸整数、奇数宽吸半整数（`snapStem`），于是笔画两侧边落在像素边界、羽化斜坡上没有可抹的东西；两端走同一计算，四个四边形顶点一致；斜笔在接头处与被吸的直笔差 ≤ 0.5 设备像素，圆头盖住。命中区、SVG 导出仍用名义宽度与名义位置（不动内核）。

**后果**：inspection 的 α 从 0.92 / 0.80 **回到 0.65 / 0.35**——sRGB 里混合，留下的不透明对比就是系数本身（≈ 65 % / 35 %，正是 2026-09-13 的本意）；ADR 0061「α 重定」段那句「改成在 sRGB 空间混合要把整条 overlay 挪出 composer 的线性目标，不值」到此翻过来：为文字清晰挪出来之后，α 顺带回到直觉值。ADR 0062 的胶囊解析抗锯齿仍是描边唯一的抗锯齿（MSAA 与 FXAA 都不再相关）；其「实心遍 engineering 不透明、羽化遍始终混合」不变。宿主的 `OutlinePass` 不再看见叠层（此前它的深度遮罩 pass 会用覆盖材质画一遍叠层网格）。`DimensionViewport.overlayScene` 是探针 / 测试找 `dimension-scene-overlay` 的地方。

**否决**：只在片元里给深色笔画的覆盖率加感知曲线（coverage^0.45 模拟 sRGB 混合）——近似，且 FXAA 与 ACES 仍在、两条路径仍不一致；用相机 layers 在 composer 内部给叠层加一道 RenderPass——仍在 OutputPass 之前，仍被色调映射、仍线性混合；MSDF 纹理字体——ADR 0062 已否，理由不变；把字形每个顶点都吸到像素格——曲线与斜笔被扭成锯齿，只吸横竖笔；笔画宽向上取整（更粗）——取最近整数，1.25× 上 2.25 → 2 个设备像素（1.6 CSS px）比模糊的 2.25 更清楚；把文字改成 Canvas 2D 位图——放弃 LFF 笔画字体与 SVG 一致性。
