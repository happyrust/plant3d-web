## 1. 目标

本计划用于跟进批注截图增强推送后的联调、验证和工作树收尾，确保功能在真实三维校审流程、PMS 嵌入流程和后端附件服务中闭环。

## 2. 已完成基线

已完成并推送：

- 截图主数据路径统一为 `screenshot`。
- cloud 旧字段 `thumbnailUrl` / `attachmentId` 兼容读取与写入镜像。
- 截图上传透传 `sourceAnnotationId`、`description`、`annotation_screenshot` 类型。
- 工作区、表格、时间线展示截图缩略图和大图预览。
- 错误类型统一为“原则错误 / 一般错误 / 图面错误”。
- 删除批注和重拍截图异步清理旧附件。
- 中文 changelog 和开发计划已归档。

已验证：

- 目标测试 77 个通过。
- `npm run type-check` 通过。
- 相关文件 `ReadLints` 无诊断错误。

## 3. 下一步联调任务

### 3.1 后端附件上传字段确认

目标：确认后端对新增 FormData 字段的处理方式。

检查项：

- `sourceAnnotationId` 不会导致上传接口拒绝。
- `description` 能在附件记录中保留。
- `type=annotation_screenshot` 能被后端正确存储或忽略。
- 返回附件的 `uploadedAt` 可信，可作为 `capturedAt`。

建议验证：

- 在真实任务中添加截图，抓取 `/api/review/attachments` 请求。
- 检查后端返回附件记录和数据库/日志。

### 3.2 附件删除行为确认

目标：确认旧附件清理不会误伤用户数据。

检查项：

- 删除批注后，旧截图附件 DELETE 请求发出。
- 重拍成功后，旧附件 DELETE 请求发出。
- DELETE 已不存在附件时，后端返回口径可接受。
- DELETE 失败时前端仅 toast 警告，不阻断本地删除。

### 3.3 多角色流程验证

目标：确认截图可跨角色查看。

建议路径：

1. SJ 创建云线批注并添加截图。
2. 保存/提交校审数据。
3. JH 或 SH 进入处理页面。
4. 在工作区列表、详情、表格、时间线中检查截图是否一致显示。
5. 执行已修改/同意/驳回动作，确认截图不会丢失。

### 3.4 PMS 嵌入流程验证

目标：确认 PMS 入口进入三维校审后截图 URL 可访问。

检查项：

- PMS 嵌入页面可加载缩略图。
- 跨登录角色后截图 URL 权限仍正确。
- 若附件 URL 需要鉴权，确认前端访问方式符合后端约定。

## 4. 工作树收尾建议

当前 `plant3d-web` 工作树仍存在大量本轮前未提交改动。建议单独处理：

1. 分类查看未提交变更：配置删除、临时文件、文档、业务代码。
2. 删除或忽略 `.tmp/`、wiki、截图等明确临时产物。
3. 对业务代码改动分主题提交，避免继续混入后续功能。
4. 若需要干净 PR，基于最新 `main` 新建分支再 cherry-pick `373e326`。

## 5. 可选增强

暂不建议立即实现 localStorage base64 离线兜底。若确实需要，应单独设计：

- 存储位置优先考虑 IndexedDB，而不是 localStorage。
- 需要限制截图数量和总大小。
- 需要明确用户隐私和清理策略。
- 需要处理离线重试与附件重复上传。

## 6. 验收标准

完成后应具备：

- 后端确认新增上传字段兼容。
- 删除/重拍附件清理路径在真实接口下可用。
- SJ/JH/SH 至少两种角色能看到同一批注截图。
- PMS 嵌入入口截图展示正常。
- 当前脏工作树有明确清理或分拆计划。
