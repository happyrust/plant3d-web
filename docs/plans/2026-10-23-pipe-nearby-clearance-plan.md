## 0. 一句话概述

周边检测在 0.1.43 上线后能用了，接口也快（65–78 ms），但它**会漏管，而且不自知**。直管段（隐式 TUBI）不进空间树，接口只从后端内存投影里补直管段；邻管只要没被谁加载过，它的直管段就不参与候选。146830 半径 500 mm 内，同区逐根精算有 14 根管，接口漏了 3 根（268 / 395 / 471 mm，最近处都是直管），回包却说覆盖完整。把这 3 根在三维里加载一次后，接口就能找到——结果取决于服务端此前碰巧加载过哪些模型（投影全进程共享，谁加载的都算）。另外，源管自己没加载时接口直接 404。后端已有从库里冷读整根记录、冷读直管段的现成读法；本计划用它们先修这两条，再提候选精度，最后整理前端的周边结果呈现。

**确认没问题的**
- 接口本身快（65–78 ms）。
- 候选规则例程全过：排除自身、成员去重、排除历史投影和无效直管段、分页。
- 精算口径一致：146830↔146810 = 184.5 mm，与「所有管对」的结果一致。
- 前端对没有这条路由的旧服务端会提示「版本不支持」并收起入口。

**可以直接复用的现成能力**
- `model_record_reader::records_of_root`：取整根记录，投影里有回执就取投影，否则从库里冷读（不写回投影）。
- `spatial_tree_tubes::load_tube_records`：按 BRAN 取直管段，投影优先，其余一次冷读 `tubi_relate`（走 `in` 索引）。房间层级树 `tubes=1` 在用。
- `spatial_query` 的 `source_mode=bran_centerline`：源取 E3D 库里的中心线走廊，不要求模型已加载；候选按段探针（`collect_corridor_candidates`）。距离从中心线起算，不含外径和管件外伸。
- 前端 `useSpatialQuery().isolateRefnos`（空间计算面板「X 光查看」在用）和 `showModelByRefnosWithAck`（按 refno 加载模型并等回执）。

## 2. 任务拆解（N1–N7）

### N1：直管段覆盖不再依赖内存投影（后端，修 G1）

1. 先量规模（只读）：线上库 `tubi_relate` 行数、BRAN 根数、全量读一遍直管段盒的耗时。据此确认 D1。
2. 按 D1(a)：后端启动后在后台从 `tubi_relate` 读各段直管的世界盒，按容器 BRAN 求并集，建「每根 BRAN 的直管段并集盒」索引，每根一个盒。有投影回执的根以投影为准；根重新生成或被逐出投影时按根刷新。
3. 候选改成三路合并：树上的管件、直管段索引、投影。索引没建好时回包把 `truncated_candidates` 置上，`warnings` 写明「直管段索引建立中，未加载的邻管可能漏检」。
4. 单测：没加载的邻管只靠直管段靠近时也要进候选；索引没建好时回包标覆盖不完整。
5. 验收：后端重启后不加载邻管，146830 也能找到 144960 / 145892 / 146146；同区逐根精算比对 0 漏。

### N2：源管没加载时不 404（后端，修 G2）

1. 按 D2(a)：拿空间树读锁之前，用 `model_record_reader::records_of_root` 预取源管整根记录（投影优先，否则冷读库，不写回投影），算出并集盒和各叶子盒。做法和 `source_mode=bran_centerline` 预取中心线一样。
2. 库里也没有这根管的模型时才回 404，消息写「这根管道还没生成模型」。
3. 回包 `center.source` 仍是 `refno_aabb_center`：前端会校验这个值。
4. 单测：投影为空时，源管从库里取盒。
5. 验收：后端重启后不加载任何模型，直接对 146830 做周边检测返回 200。

### N3：候选按源管逐件筛、只扫源管附近（后端，修 G3、G4）

1. 源管按叶子盒逐个探针取树上候选（同 `collect_corridor_candidates` 的逐段探针加去重），候选距离取「源管各叶子盒到候选盒的最小距离」。叶子盒包住几何，所以仍然保守，不会漏。
2. 投影里的根按回执缓存整根并集盒；请求时先用并集盒粗筛，粗筛过了再看逐条记录，不再每次遍历整个投影。直管段索引同样先粗筛。归属不明只统计这个范围里的。
3. 验收：145018 候选 13 → 约 6，144872 8 → 约 0（同区模拟值），146830 变化不大；同区比对 0 漏；接口耗时不随投影根数明显增长。

### N4：一对多精算（后端，修 G8，按决策 D3 可缓做）

1. 提供一对多的外表面净距：源管网格只加载一次，一次请求返回各候选的结果。
2. 前端周边检测改用它，一次周边检测的精算请求从 N 个降到 1 个。

### N5：周边结果单独成组，不改选择（前端，修 G5、G7）

1. 周边检测后选择仍是源管；周边候选另存，不写进 `selectedBranRefnos`。
2. 结果单独一组，标题「146830 的周边：N 根在 500 mm 内」，按净距从近到远排，相交的排最前。
3. 提供「重新检测周边」和「只看周边」。「只看周边」复用 `useSpatialQuery().isolateRefnos`：源管和周边管实体显示，其余 X 光。
4. 单测：周边检测不改选择；结果按净距排序。

### N6：提示分级（前端，修 G6）

1. 没找到周边管 → 普通提示，不是红字。
2. 覆盖不完整 → 黄字，照搬后端写的原因；不再一律建议「缩小最大距离」。
3. N2 上线前，源管没加载的 404 改写成能照着做的提示（例如「服务端还没加载这根管道的模型，请先在模型树里显示它再检测」），文案以实测为准。

### N7：验收脚本固化（验证）

1. 把本次的候选比对脚本（周边候选 × 同区逐根精算）放进仓库，覆盖三种场景：后端冷启动、密集管廊、长多段管。
2. 指标：漏检数必须为 0；候选精度、接口耗时、精算请求数记入验证记录。

## 3. 需要 Plannotator 拍板的决策（D1–D5）

| # | 决策项 | 推荐方案 | 备选方案 |
| :--- | :--- | :--- | :--- |
| **D1** | 直管段覆盖怎么补（N1） | **(a) 推荐**：后端启动后在后台从库里建「每根 BRAN 的直管段并集盒」索引，候选判定用它；有投影回执的根以投影为准。每根只存一个盒，内存很小。 | (b) 给直管段单独建一棵空间树（每段一个盒）：候选侧也能逐段算距离，精度更高；但内存随直管段数增长，换版时要逐段维护。<br>(c) 只改口径：邻管没加载就标覆盖不完整，不补。<br>每次请求去库里按盒查 `tubi_relate` 不可行：库里没有空间索引，等于每次全表扫。 |
| **D2** | 源管没加载时怎么办（N2） | **(a) 推荐**：服务端预取源管整根记录（投影优先，否则冷读库），不依赖内存投影。 | (b) 前端先用 `showModelByRefnosWithAck` 加载源管再调接口：只修 G2，不修 G1。<br>(c) 源改用现成的中心线走廊（`source_mode=bran_centerline`）：不要求模型已加载，但距离从中心线起算，要按外径和管件外伸加余量；阀门手轮这类外伸大的件可能漏。 |
| **D3** | 精算请求量（N4） | **(a) 推荐**：先不做一对多接口，N1–N3 上线后看实际候选规模再定。 | (b) 这一轮就做一对多接口。 |
| **D4** | 周边结果怎么呈现（N5） | **(a) 推荐**：单独一组、按净距排、不改选择，带「重新检测周边」和「只看周边」。 | (b) 维持现状：和所有管对共用一个列表，只修排序。 |
| **D5** | 周边检测的范围（G9） | **(a) 推荐**：抽屉的周边检测只管管道（精算）；墙、柱、楼板、设备走空间计算面板，两边互相跳转。 | (b) 抽屉周边检测扩到全部类型。<br>(c) 合并成一个「周边净距」入口。 |
