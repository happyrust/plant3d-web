## 0. 怎么用这份计划

**演示对象是已部署到服务器的线上环境**（`http://123.57.182.243/`），本机只负责显示与录制。按下面顺序走：

1. **部署对齐**（§1.1.1）：推送 + 触发部署，`version.json` 的 commit 对上要演示的 HEAD。
2. **几何预热**（§1.1.3）：先跑一次模型生成，否则 S08 / S09 / S11 会以「没有包围盒」失败。
3. 过一遍 **§1 录制前准备**，把数据、账号、浏览器备好，逐项勾完 **§6 检查清单 · 录制前**。
4. 按 **§2 录制顺序**（不是编号）逐段录制；录每一段时对照 **§7 分镜与旁白稿**，S13 另按 **§8 真实 PMS 操作与校验点** 执行，Bandicam 设置与起停见 **§9**；每录完一段，按 **§6 · 录制中** 自检一次。
5. 全部录完后按 **§4 剪辑与交付** 整理（含 chengfeng-videocut 账本制流程），命名、封面、字幕统一。
6. **附录 A** 是功能点总表，每个功能点都映射到一个片段编号——录完后逐行打勾，确认没有漏掉的功能。

一键核对线上状态：`powershell -NoProfile -ExecutionPolicy Bypass -File docs/demo/Start-DemoEnv.ps1`。脚本只读检查版本、健康、空间树、房间归属、几何预热状态与 S11 样例，不启动任何本机服务。

时长标注是**成片时长**（分钟），不是录制耗时；实际录制建议每段多录 1–2 遍备用。

#### 1.1.1 部署与版本对齐（录制前必做）

现网版本落后本地开发线时，录出来的画面与代码、与教程、与 `CHANGELOG.md` 都会对不上。**先把线上版本对齐到要演示的提交，再开录。**

```powershell
# 1. 确认本地要演示的分支与提交
git rev-parse --short HEAD

# 2. 推送到远端（部署 workflow 按 --ref 部整个分支）
git push origin main

# 3. 触发部署（约 2 分钟：npm ci → build-only → 写 version.json → rsync → nginx reload）
gh workflow run deploy-ubuntu.yml --ref main
gh run list --workflow deploy-ubuntu.yml --limit 2
gh run watch <run-id> --exit-status

# 4. 验收：version.json 的 commit 必须等于刚才推的 HEAD，bundle hash 应变
curl.exe -s http://123.57.182.243/version.json
curl.exe -s http://123.57.182.243/ | Select-String 'assets/index-'
```

部署口径要点：

- **部的是整个分支**，`--ref` 指到哪就部到哪，不能只挑某几笔；只想上一部分就先切 `deploy/<日期>` 分支再 `--ref` 它。
- 部署脚本只覆盖 `sites-available/plant3d-web`（`listen 80; listen 3100;`），线上 443 不在该文件里，覆盖后 HTTPS 照常。
- 部署分支用 `build-only` 出包，`type-check` 基线漂移不挡部署；这不代表类型检查通过。
- 后端（gen-model）走另一条线：`publish` 分支推送即触发 `linux-binary.yml` 构建并部署。**只有前端需要重部时不要动后端。**
- 录完把本次 commit 记进 `recordings/README.md` 的「前端 commit」一行——同一部片的 16 段必须来自同一 commit。

**录制期间不要重新部署。** 中途换包会让前半段的界面与后半段不一致，剪辑时对不上。

#### 1.1.2 线上数据边界

本次录制**全部在线上进行**，接受在服务器留下演示数据。需要事先知道后果：

| 片段 | 会写入什么 | 影响 |
| --- | --- | --- |
| S10 模型生成 | 生成记录、增量批次、几何缓存 | 只增不减；大范围生成会占内存，演示只选小 SITE 或单根 BRAN |

| S13 校审 | 编校审单、附件、流转记录 | 会出现在 PMS 待办里；包名用时间戳区分，避免与真实单据混淆 |

#### 1.1.3 几何预热（S08 / S09 / S11 的硬前置）

2026-10-27 实测：**线上服务器还没有生成过任何几何。**各库 `model/roots` 的 `ready_total` 全为 0；对房间 `R432` 里的 BRAN（如 `24383_67619`）调空间查询，服务端回
`404 not_found:"构件 … 在模型投影与空间树里都没有包围盒（还没生成过模型）"`。

后果很直接：**不预热就录，S08 空间查询会 404、S09 中心线净距选不到可算的 BRAN、S11 的「在三维中对比」会没有几何可装。**

预热步骤（拍摄前一天或开录前 1 小时做一次）：

```text
1. 打开 http://123.57.182.243/?output_project=AvevaMarineSample&show_dbnum=8000
2. 视图 → 模型生成，选一个「演示不会用到」的小 SITE，点生成，等进度跑完
3. 复验：/api/v1/dbnums/8000/model/roots 的 ready_total 从 0 变成非 0
4. 复验：滑块到目标 BRAN 上，空间查询能返回结果而不是 404
```

**预热目标与演示目标必须错开。** S10 要演示的正是「点生成 → 进度 → 完成」，如果演示目标已经生成好，面板会直接说已就绪、没有进度可看。做法：

| 片段 | 用哪个目标 |
| --- | --- |
| 预热（不录） | 一个小 SITE，例如某个 `STRU` 根 |
| S08 空间查询 | 预热过的区域内的设备 |
| S09 中心线净距 | 预热过的 BRAN |
| S10 模型生成 | **另一个**未生成的小 SITE 或单根 BRAN |
| S11 版本对比 | 预热过的 FTUB `24384_23262` / PIPE `24384_23225` |

S11 还有第二层预热：历史投影是**首次查询时按需生成**的，要几秒到十几秒。开录前对两个样例各跑一次 URL 直达（§1.2），把缓存热起来；否则第一次点「在三维中对比」会卡在加载动画上。

**版本对比的接口口径（S11 必读）**

线上两套版本接口，适用范围不同，录 S11 时别选错：

```text
model/versions   只接受「最小交付单元根」，即 BRAN / HANG / SUPPO / EQUI
                 传 FTUB 或 PIPE → 422 NOT_A_DELIVERY_UNIT_ROOT
node/versions    ADR 0066「任意节点 + 对比范围开关」，FTUB / PIPE / 任意节点都能查
                 面板默认走这条；scope=self 仅自身、scope=subtree 含子树
```

实测：`node/versions?dbnum=8000&refno=24384_23262&scope=subtree` → 53 版；
`node/versions?dbnum=8000&refno=24384_23225&scope=subtree` → 153 版。
若录制时面板报「不是最小交付单元根」，说明前端退回了 `model/versions` 旧路径——**换 BRAN 演示，不要在现场排障**。

### 1.3 账号与角色

- 前端角色体系：`admin / manager / reviewer / proofreader / designer / viewer`（`src/types/auth.ts`）。「批注单」只对 designer / proofreader / reviewer / manager / admin 可见，「我的编校审」只在工作流模式下出现——**录 S13 前先确认当前登录角色**。

### 1.4 录屏工具与规范

- 工具：**Bandicam 便携版**，路径 `D:\Download\Bandicam_8.3.0.2533_Portable_64Bit\Bandicam-8.3.0.2533-x64-Portable\Bandicam\BandicamPortable.exe`。录制模式选「屏幕录制 → 全屏」，输出 **2560×1440、30fps、mp4（H.264）**，开启「显示鼠标指针」与「鼠标点击效果」，关闭 FPS 叠加显示；若为未注册版本会带水印与单段时长限制，录制前先试录 10 秒确认。
- 片段命名：`S01-框架与界面.mp4`、`S02-显示与外观.mp4` …（编号与 §2 一致）。
- 旁白：**先说目的，再做操作，最后指出结果**（「现在要看这根管周围 5 米内有什么 → 点执行 → 结果按专业分组，共 N 项」）。
- 每段开头 2 秒停在干净的初始画面，结尾 2 秒停在结果画面，方便剪辑切换。
- 画面里不要出现：DEV 调试面板（LOD Debug）、「调试」页签、浏览器 DevTools、任何密码。

**地址栏的处理（改成服务器演示后新增）**

站点地址 `http://123.57.182.243/` 本身可以入镜——它是公开演示站，观众点开也能看。但**三处必须遮蔽**：

1. **PMS 嵌入 URL 里的 `user_token`**：PMS 打开三维窗口时地址形如
   `http://123.57.182.243/review/3d-view?form_id=<FORM>&user_token=<JWT>&output_project=...`。
   这个 `user_token` 是**按人签发的 JWT，24 小时有效**，泄露等于把该账号的访问权交出去。
   S13、S14 录完必须逐帧检查这一段，剪辑时打码或直接裁掉地址栏。
2. **PMS 顶栏的账号 / 姓名**，以及登录页的账号输入框。
3. **任何密码框**——录制时输入框应只显示圆点，旁白不念密码。

录 S13 前先在浏览器里按一次 F12 打开 DevTools 再关掉，确认关闭后地址栏不会被自动填充或历史下拉暴露上一条带 token 的 URL：**录制前清空该 Chrome 配置的浏览历史与地址栏联想**，或直接用一个新的无痕窗口。

### 1.5 布局与状态归零

录每一段之前都执行一遍，保证画面一致：

1. 「视图 → 布局 → 重置布局」。
2. 菜单模式统一（建议**普通分层菜单**，更贴近 CAD 用户习惯；S01 里会专门演示切换）。
3. 「测量 → 管理 → 清空」、「测量 → 清空净距」、「校审 → 数据 → 清空」把上一段留下的测量/批注清掉。
4. 相机回到全景（全部显示 → 定位显示）。
5. 如果上一段改了显示主题 / 绘制样式 / 背景，恢复默认。
6. **确认清空已落到服务器**：清空后按 `Ctrl+R` 刷新一次页面，重新打开测量 / 批注面板确认为空。线上数据是持久化的，只在前端点了「清空」而请求失败时，下一段会带着上一段的残留入镜。
7. **确认没有别人的数据入镜**：这台服务器是共享的。S13 的待办列表、S14 的批注单里可能出现他人或历史单据——录制时只打开本次要演示的那一条，列表页停留时间尽量短。

录制顺序建议与 §2 的编号一致，但 **S13 / S14 放在最后录**：它们会往线上写入编校审单与附件，一旦先录，后续片段的面板里就会出现这些单据。

## 4. 剪辑与交付

### 4.1 工具：chengfeng-videocut（已装好，可用）

本机已安装 `chengfeng-videocut` 0.4.11，常驻服务跑在 `http://127.0.0.1:5190`（Windows Task Scheduler 托管）。它按**账本制**工作，四段独立、每段只产出一件东西：

```text
剪口播  → 删词账本(EDL)   逐词转录 → 词典修字 → 五轮扫描 → Studio 人工复核。不碰媒体
字幕    → subtitles.json  从账本现算时间，不存秒数，只存词 id
画面    → visuals.json    HTML 层，绑字幕屏，不是绑秒
导出    → 成片.mp4        assemble → overlay → compose → verify
```

核心是**绑词不绑秒**：字幕和画面层都锚在词 id 上，剪掉一段话，字幕和层自动跟着挪。

**前置：云端转录凭证**。转录走火山引擎，未配置时会在第一步报
`missing_cloud_transcription_adapter`：

```powershell
node "$env:USERPROFILE\.agents\skills\chengfeng-videocut\scripts\videocut-cli.cjs" config set transcription.apiKey <key>
```

还需要 `transcription.resourceId` 与 `transcription.modelName`。这是付费云服务，凭证由使用者提供。

### 4.3 与 16 段结构的三处不匹配（必须先定方案）

| 冲突 | 说明 | 建议做法 |
| --- | --- | --- |
| 单项目单源视频 | `project create` 只接一个 `--video`，没有「追加素材」命令 | **每段一个独立项目**，分别导出，最后用 `ffmpeg concat` 拼总片；精简版在 concat 阶段选段 |
| 转录会把操作音当噪声 | 敲键盘、点菜单的间隙会被识别成无意义音节 | 五轮扫描大多会把它们当残句删掉；有误删有效解说的风险，靠 Studio 那轮人工复核兜底 |
| S13 四幕跨四个角色 | 每段账号区位置不同，打码层要逐段做 | S13a–d 各自独立处理，不建议走整条链；用 HTML 遮罩层 + concat |

另有一条**分辨率**依据：导出 skill 的规则是「源宽 ≥2560 → `--scale 1`，输出原生像素」。本计划已改 2560×1440，正好命中这一档——字幕与动画按输出尺寸重画，比 1080p 更清晰。

## 8. 真实 PMS 环境下 S13 的逐步操作与校验点

### 8.1 录制前演练（必做）

- 用 SJ 完整走一遍 发起 → 保存 → 送审，确认：① 三维窗口能加载（模型树 / 三维 / 校审面板齐）；② 「发起编校审」里流程人员下拉非空；③ 送审后回到「三维校审单」列表能看到包名行；④ JH 登录后待办里有这条。演练用的单子在正式录制前作废或改名，避免录制时列表里有两条同名。
- **三维窗口加载的是线上部署的前端**（`http://123.57.182.243:3100/`）。演练前先确认 §1.1.1 的版本已对齐、§1.1.3 的几何已预热——否则三维窗口能打开但模型不显示，会被误判成 PMS 故障。
- 包名命名：`DEMO-三维校审-YYYYMMDD-HHMM`，正式录制用新的时间戳；旁白里念包名，便于后期核对。

### 8.2 多角色切换

- 推荐：给 SJ / JH / SH / PZ 各开一个独立的 Chrome 用户配置（或各一个无痕窗口），窗口标题栏写上角色名；切角色 = 切窗口，避免同一会话被踢。

## 9. Bandicam 配置与录制流程

### 9.1 一次性配置

- 程序：`D:\Download\Bandicam_8.3.0.2533_Portable_64Bit\Bandicam-8.3.0.2533-x64-Portable\Bandicam\BandicamPortable.exe`
- 模式：「屏幕录制」→「全屏」（**2560×1440** 显示器）；多屏时选主屏。
- 视频：MP4 / H.264（有 NVIDIA 显卡优先选 NVENC 编码器，减轻 CPU 负担、避免三维掉帧）/ 30 fps / 质量 90 以上 / **分辨率原始尺寸（不要缩放）**。
  - 保持原生 2560×1440 的原因：剪辑端导出规则是「源宽 ≥2560 → `--scale 1`，输出原生像素」，字幕与动画按输出尺寸重画。缩到 1080p 再放大不会变清楚。
- 音频：主音频设备选麦克风；不需要系统声音就关掉（避免 Chrome 提示音入镜）。
- 录制选项：勾「显示鼠标指针」「鼠标点击效果」（左键）；关闭 FPS 叠加显示与 Bandicam Logo 水印选项（已注册版）。
  - **水印必须在录制前解决**：它烧进源片，剪辑阶段无法去除，只能重录。
- 快捷键：开始 / 停止 F12，暂停 / 继续 Shift+F12（Bandicam 默认；若与其它软件冲突改成 F9 / F10 并在此记录）。
- 输出目录：`D:\Recordings\plant3d-demo\`；文件名模板保留默认（含时间戳），录完立即按 `S01-框架与界面.mp4` 规则重命名。
- 未注册版有水印和 10 分钟单段限制；S13 成片 6 分钟、留 2 分钟余量仍在限制内，其它段如果一镜到底超过 10 分钟会被截断——按幕拆录。

### 9.2 每段录制流程

1. 按 §1.5 状态归零；把 Bandicam 窗口最小化到托盘。
2. **确认线上还在演示的那个 commit**：另开一个标签页看 `version.json`，与 `recordings/README.md` 记的一致再开录。
3. 鼠标移到视口外，静止 2 秒 → 按 F12 开始。
4. 对照 §7 分镜操作并念旁白；说错一句就停 2 秒重说这一句，不要从头来（后期剪）。
5. 结束画面静止 2 秒 → F12 停止。
6. 立即在 Bandicam「主页 → 视频」里回放：检查画面完整、声音清晰、没有不该入镜的内容（尤其地址栏）。
7. 重命名文件；在 §6 清单与附录 A 对应行打勾。
8. 卡顿或翻车：Shift+F12 暂停处理完再继续，或直接停止重录该段。

### 9.3 常见问题

- 画面黑屏 / 只录到桌面：切回「屏幕录制」模式（不是「游戏录制」）。
- 三维明显掉帧：改用 NVENC 编码，或把质量降到 80；确认 Chrome 没有被其它录屏软件同时抓取。
- 鼠标指针没录到：录制选项里「显示鼠标指针」未勾。
- 声音有回声：关闭系统声音录制或戴耳机。
- **转圈很久不出模型**：先分辨是网络还是几何未预热——按 §5 的两条不同回退处理，不要当成产品缺陷录进去。
