## 7. 缺失 / 弱项盘点（按优先级）

### P0 - 流程链路有断点

**P0-1：嵌入页"保存编校审单数据"未触发 workflow 实例化**

- 证据：`artifacts/browser-use-reject-20260425-1002/report.md` ISSUE-001；
  `artifacts/pms-simulator-return-trace-20260425-100008.json` `return-sync` 断言
  `workflow next_step 缺失，仅可查看`；
  `artifacts/pms-simulator-reject-20260425-095905.json` `gate-return` HTTP 403。
- 对照：`contractSmoke` 7/7 全过，靠的是显式 `review-task(seed)` 这一步；嵌入页保存路径没有等价调用。
- 影响：SJ → JH 链路从源头断，browser-use 报告里的 ISSUE-002（JH 看不到任务）是派生现象。
- 修复方向（A 最小改动 / B 更贴真实 PMS）：
  - **A**：`InitiateReviewPanel.vue` 保存接口在写入构件/数据包后，按 `project + form_id` 自动 seed
    一条 workflow 实例（`next_step=jh` / `assignee=JH`），等价 `review-task(seed)`。
  - **B**：保留"保存"只落数据，"送审"按钮才 seed workflow；但需同步修前端"未送审也强制
    readonly"的状态机。

**P0-2：CUTOVER 写入路径不一致**

- 证据：`docs/verification/三维校审完整流程审查文档.md` 第 8 节 P1-1、P1-2。
- 现象：
  - `src/composables/useToolStore.ts:1497-1528` `setAnnotationComments()` 仅写 inline
    `annotation.comments`，但 `getAnnotationComments()` 已切到 `commentThreadStore`
    → 后端返回评论后界面仍显示为空或旧数据。
  - `_isCommentStoreActive()` 硬死成 `true` → 回退开关 `REVIEW_C_COMMENT_THREAD_STORE_CUTOVER=0`
    / `review.force_legacy=1` 失效。
- 修复方向：
  - `setAnnotationComments()` 同步写入 `commentThreadStore`。
  - 恢复 `isReviewCommentThreadStoreActive()` 在 `useToolStore` 的真实调用。
  - 补测试：后端加载评论 → 时间线能显示；关闭 CUTOVER → 读路径回 inline。

### P1 - UI / 角色覆盖空白

**P1-1：发起人侧 onboarding guide 缺失**

- 现状：`src/components/onboarding/roleGuides/` 只有 `reviewerGuide.ts` 和
  `hierarchicalMenuGuide.ts`。
- 现象：`ReviewGuideCenter.vue` 是双角色入口，但发起人路径无引导文案可读。
- 建议：新增 `designerGuide.ts`，与 `reviewerGuide.ts` 对称，覆盖发起/看板/退回处理三条主动作。

**P1-2：`review-reviewer.pen` / `review-flow.pen` 设计稿文件在仓库内未命中**

- 现状：`ui/三维校审/` 下 Glob 只找到 `review-designer.pen`。
- 对照：`三维校审角色设计稿归属表.md` 与 `三维校审阶段执行总览.md` 大量引用这两份主稿。
- 建议：
  - 确认这两份文件是否仍存在、是否被 `.gitignore` 吃掉、是否路径变更。
  - 若已废弃，同步更新归属表与阶段总览中的引用。
  - 若还在用，补提交或恢复路径。

**P1-3：批注门禁角色配置错**

- 证据：`pms-simulator-reject-20260425-095905.json` `gate-return` scenario
  `POST /api/review/records 失败：当前用户 SH 不是 checker 节点负责人 JH`。
- 现象：`gate-return` 场景强行让 SH 调 `/api/review/records`，但 checker 节点负责人是 JH。
- 建议：仿真器 `gate-return` 用例改为 JH 角色调用；或调整 seed 时把 checker 节点负责人写对。

### P2 - 可测性

**P2-1：嵌入页 iframe 内关键控件未暴露 a11y ref**

- 证据：`browser-use-reject-20260425-1002/report.md` ISSUE-003。
- 现象：`agent-browser snapshot -i` 在主页面只稳定暴露 PMS 外壳按钮；iframe 内
  "构件输入 / 数据包名称 / 保存编校审单数据"不作为普通 ref 暴露。
- 建议任一或组合：
  - 给关键控件补 `aria-label`、`aria-controls`、`data-testid`。
  - E2E 改用 Playwright frame locator，而非顶层快照。
  - 提供 `window.__plantReviewDebug` 这类 debug 句柄给自动化直接调用。

**P2-2：缺端到端"驳回回路"自动化用例**

- 现状：`e2e/` 下只有 `pms-powerpms-review-new.spec.ts`（新建）和
  `pms-review-simulator-token-only.spec.ts`（token），没有 reject-and-resubmit。
- 建议：新增 `e2e/pms-review-simulator-reject-and-resubmit.spec.ts`，覆盖
  "SJ 发起 → JH 驳回 → SJ 处理批注 → 重提 → 通过"；同时作为 P0-1 / P0-2 修复后的回归门。

### P3 - 可维护性

**P3-1：`pms-review-simulator.html` 是 1170+ 行原生 HTML/JS**

- 现状：与 `src/debug/pmsReviewSimulator*.ts` 双源维护，协议一旦调整两边容易漂移。
- 建议：短期可保持；中期迁回 Vue 组件化或至少抽 TS 入口统一发送 payload。

**P3-2：`wiki/Plant3d-web/raw/sources/` 下存有 `src/components/review/` 的镜像副本**

- 现状：Glob `**/review*` 返回的 191 条结果中有一多半落在 `wiki/.../raw/sources/`。
- 影响：搜索结果被污染，易误改旧版文件。
- 建议：添加 `.cursorignore` 或 `.gitattributes` 规则排除 `wiki/**/raw/sources/**`；
  或把它明确标记为归档目录。

**P3-3：Dock 面板没有显式"角色切换"入口**

- 现状：`RoleSwitcher.vue` 仅在 `pms-review-simulator.html` 内挂载；
  `App.vue` / `DockLayout.vue` 没暴露。
- 影响：真实 PMS 靠 token，但 dev/QA 调试角色必须改 URL。
- 建议：在 `debug_ui=1` 模式下，把 `RoleSwitcher` 挂到右上角工具条，只在 debug 门禁开启时渲染。
