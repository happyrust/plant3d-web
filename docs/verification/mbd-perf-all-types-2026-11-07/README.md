# MBD 各类型真实对象的性能复核（2026-11-07，#103 M7）

结论：40 m 建筑楼板 `24381_38695`（794 条记录）相机环绕时的布局 p95 原先是 110–120 ms，根因是三维标签卡片的避让计分逐候选扫遍全部文字框与尺寸线段。
改成屏幕网格查找、提前截止与线段外包盒预判后降到 23–25 ms，其余对象同步变快；六个对象的绘制数与重叠数前后逐一相同（摆位不变）。

## 跑法

验收脚本 `e2e/mbd-label-overlap.spec.ts`，`MBD_LABEL_OVERLAP_PERF_RUNS=3`：每个对象三次相机环绕，每次 120 帧，记 `window.__dimensionFrameStats`
的布局 / 绘制 / 整帧 p95。dev 构建、1920×1080、本机 Chrome headless（真显卡）；几何读 8022，MBD 读 8023（gen-model `feat/mbd-all-types`）。
同机还有两路编译在跑，数值偏保守。

注意：脚本先拍远 / 中 / 近三档截图，再「回到远档」时只等相机停稳、不复位，所以**环绕实际在近档相机（拟合距离的 0.2 倍）下进行**，
标签全部按细节档展开，是最重的情形。

```powershell
$env:MBD_LABEL_OVERLAP='1'; $env:GEN_MODEL_V1_BASE_URL='http://127.0.0.1:8022'; $env:MBD_LABEL_OVERLAP_MBD_BASE='http://127.0.0.1:8023'
$env:MBD_LABEL_OVERLAP_OUT='docs/verification/mbd-perf-all-types-2026-11-07/after'; $env:MBD_LABEL_OVERLAP_MODES='off'
$env:MBD_LABEL_OVERLAP_REFNOS='24381_38695,17496_80024,17496_118364,24383_69033,24383_76360,24381_145018'
$env:MBD_LABEL_OVERLAP_PERF_RUNS='3'; $env:PLAYWRIGHT_PORT='3133'
npx playwright test e2e/mbd-label-overlap.spec.ts --config=playwright.novideo.config.ts --workers=1
```

`before/` 是修正前同一命令的 `diag.json`（截图与修正后相同，未保留），`after/` 是修正后的截图与 `diag.json`。

|---|---|---|---|---|
| `24381_38695` | 建筑楼板（约 40 m，794 条记录） | 464 | 115.0 → 23.9 | 135.3 → 39.2 |
| `17496_80024` | 土建楼板（埋板） | 106 | 15.1 → 8.5 | 25.8 → 23.4 |
| `17496_118364` | 土建 GWALL | 121 | 17.7 → 11.4 | 30.2 → 25.9 |

绘制 p95 各对象都在 15–19 ms，与标签多少无关。

对照：ADR 0040 的预算是参考环境（DPR 2）下 2000 条可见尺寸整帧 p95 ≤ 16 ms；本机 dev 档的不退化门槛取自 `e2e/dimension-perf.spec.ts`
（布局 p95 ≤ 26.2 × 1.2 = 31.4 ms，绘制 p95 ≤ 78.6 × 1.2 = 94.3 ms）。修正后最重的楼板布局 23.9 ms，在门槛内。
合成场景门禁同时复跑通过（2000 条可见：命中 p95 0.1 ms，布局 p95 16.6 ms，绘制 p95 46 ms）；内核基准 layout+collision p95 5.9 ms（上限 16 ms）。

## 根因与修正

CPU 剖析（`24381_38695`，近档环绕 60 帧）里 83% 的时间在 `placeTagBillboards` 的计分函数：每帧 203 张标签卡片、每张平均 34.5 个候选位
（密集处几乎没有空位，候选要逐个算完），每个候选扫一遍包络内的全部文字框（平均 174 个）与尺寸线段（平均 1557 段）——
每帧约 1090 万次线段裁剪、120 万次矩形求交。包络是全部候选位的并集，跨几百像素，土建的圆弧细分成大量短线段，包络过滤挡不住。

`src/dimension/kernel/layout/tagBillboard.ts` 三处改动，摆位结果不变：

1. **屏幕网格**（`src/dimension/kernel/geometry/rectGrid.ts`，64 px 一格，按视口夹取）：文字框与线段各建一张，每个候选只看同格的条目。
   条目按重叠判定自己的算法给出外延（矩形远边用 `x + width`，线段用端点的最值），按输入序返回——漏掉的都不覆盖候选，得分逐位相同。
2. **提前截止**：每一项都不为负，候选的累计分一旦为正且已不可能胜过当前最优（含首环最优），后面的项不再算。
3. **线段外包盒预判**：外包盒在候选之外的线段直接跳过，不进裁剪。

单测：`rectGrid.test.ts`（与暴力求交对照、远离视口的条目、NaN / 无穷）；`tagBillboard.test.ts` 新增一个 60 张卡片、120 个文字框、
400 段线段（含近相机的超长线段）的密集场景，网格路径与全量扫描逐项相同，且与测试里独立写的全量求和参照逐张卡片选位相同。

## 余量与观察

- 大楼板整帧 p95 仍约 40 ms（环绕时约 25 帧 / 秒）：布局 24 ms + 绘制 17 ms。绘制是尺寸线顶点每帧重写，要再降需要在绘制层做缓存，不影响正确性，记为后续项。
- 环绕时模型树面板在重渲染（`ModelTreePanel` 的 `rvmNodeBadge`，约 2 ms / 帧），与 MBD 无关，记录在此。
