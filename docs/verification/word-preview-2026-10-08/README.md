# Word 附件预览开发验证（2026-10-08）

本记录证明局部开发验证，不代表部署验收或 D07 已完成。

## 实现

- DOCX 使用已有 mammoth 依赖解析，复用附件列表、预览面板和原文件下载入口。
- Word 全量读取，限制 50MB；拒绝部分响应、错误文件头和解析失败。切换附件取消旧请求，转换结果不会覆盖新附件，失败可重试。
- 生成内容清理链接、事件及外部资源，使用空 sandbox 的 iframe 和内容策略展示。
- DOC 调用带认证的 `/api/review/attachments/{id}/word-preview`。后端只读转换并检查项目、参与人和文件路径；单机并发 2、转换超时 45 秒。

## 验证结果

- 专项检查 19/19 通过，覆盖识别、认证转换请求、原始下载地址、错误重试、附件切换和大小限制。
- 真实 DOCX 浏览器验证：中文正文、加粗、表格、DN100 可见；不可信链接删除；损坏 ZIP 拒绝；实际面板 iframe 的 sandbox 为空。样例及截图在本目录。
- 全套前端：338 个测试文件、3089 项测试全部通过。版本属性测试原有固定等待在并行负载下不足，改为等待实际查询及界面结果。
- 类型检查：503 条既有错误，基线 539 条，新增 0。未放宽基线。
- 生产构建通过。本轮改动文件 ESLint 通过；全库 ESLint 仍有 45 条错误、19 条警告，尚未满足全库无错误发布门槛。
- 后端默认配置 `cargo check --lib` 通过。隔离工作目录链接了既有 vendor 和 plant-ui 依赖。

## 复核

在前端仓库启动开发服务至 `http://127.0.0.1:3181` 后，运行 `node scripts/verify-review-word-preview.mjs`。该检查读取真实 DOCX，验证生产转换函数及附件预览组件，并保存截图与结果至本目录。设置 `WORD_PREVIEW_BASE_URL` 可更改本地服务地址。
