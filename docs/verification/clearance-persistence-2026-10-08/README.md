# 构件净距本机保存与作用域隔离（开发阶段）

## 实现

已有 `useClearanceStore` 的构件→墙拾取和空间查询抽屉的构件→构件记录现在自动写入本机存储。Viewer 绑定的作用域包含项目、库、用户、批注任务/轮次、单据、流程节点以及当前 A/B 会话和单元范围。未知项目只保留内存状态。

恢复时验证格式、所属作用域、记录标识、有限距离与端点。保留结果快照、两侧模型会话号、隐藏状态与标注开关，统一标为 `stale` 并提示重算。保存失败显式提示并在本次应用进程内保留该作用域的未落盘快照；重新切回可重试保存。损坏或错位的存储原文不会被自动覆盖。抽屉提供重算、隐藏/显示和移除入口。

清空、作用域切换、退出 Viewer 和进入历史对比会使旧请求失效；同一对构件较旧响应不能覆盖较新响应。并发时“计算中”直到当前上下文的在途请求全部结束。历史对比期间不能以当前模型接口产生历史净距。重算失败时保留旧快照，三维文字显示“重算失败，旧值”。

“本机已保存”明确注明“未提交校审”。这不是云端校审保存，也不是专业验收。

## 检查证据

- `node scripts/verify-clearance-persistence.mjs`：真实 Chromium localStorage 写入和刷新重开通过，验证完整快照、模型会话号、隐藏状态、标注开关、恢复 `stale`、作用域隔离及切回恢复。输出见 [browser-results.json](browser-results.json)。使用已有几何响应样例及真实生产 store/service；未调用真实专业/PMS 数据，不能作为业务验收。
- 最终前端全量回归：338 个文件、3114 项通过；新增 store 检查覆盖作用域切换、恢复、损坏、配额失败、迟到请求、并发倒序及历史模式切入。
- 修改文件规范检查通过；类型检查保持现有 503 条，相对 539 条基线新增 0；`npm run build-only` 通过。新增“重试保存”按钮后抽屉 37 项检查再验证通过。
- 全仓规范检查仍有 27 个错误、21 个警告，均在本轮修改文件之外；不能据此声称发布检查全部通过，仍需纳入 D17 清理和候选版本回归。
