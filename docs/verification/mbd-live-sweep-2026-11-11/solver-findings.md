### 1.2 任务 2：三面土建墙（核对过数据）

**`24381_2147`、`24381_4342`：整圆的弧墙。** SPINE 五点绕回起点（圆心 (150, 1537)，R5000 / R2770，墙厚 2230）。
根因行：`civil/self_marks.rs` 的 `auto_heights` 拿 `arcs[1]` 两端点的弦长当「写得下的长度」——PML `markCivilSelf` L5655 /
`drawarchname` L1942 也是这么取的。整圆时两端重合，弦长是 1.2e-12 的浮点残差，缩字比例 2.5e-15：名称、厚度的字高与厚度圈的
半径全缩到 1e-13。墙顶名称的方向（`civil/element.rs`，起点指向终点）在整圆上没有定义，联调后端上落成了正 E。

修正（`D-CIVIL-025`）：写得下的长度取弧上最长的弦（`Arc3::span`：半圆以内就是两端弦长，过了半圆是直径）；墙顶名称的方向按
扫角一半处的切向（`Arc3::chord_dir`，对别的弧结果不变）。两面墙各 12 个图元恢复：名称字高 350、厚度 70、厚度圈半径
94.66 / 115.66（改前 8.7e-13 / 1.7e-13 / 2.4e-13 / 2.9e-13），墙顶 `text_dir` (0.988, −0.156, 0)。

**`24381_25804`：不是墙，是竖着的 FLOOR。** 这块板沿 N 拉伸，两张 L 形面在 y = −20700.68 / −18800.68，法向 ∓N，与缺省观察方向 N
平行。PML `markCivilSelf` L5724-5732 对 FLOOR 的写法是「y is lookdir and z is 面法向」，两者平行时建不出朝向——联调后端的 `text_dir`
因此是零向量。修正（`D-CIVIL-026`，`self_marks::floor_face_ori`）：法向离观察方向不足 1° 的面照墙面取面自己的坐标系；改后
`text_dir` (1, 0, 0) / (−1, 0, 0)，`text_up` (0, 0, 1)。别的竖板（AMS 的 184 个 civil FLOOR 里 18 块、法向 E / W）照 PML 字沿竖向读，
没有动。

838 个 civil / arch 对象重算：名称 / 厚度变了的只有这三个对象。PML 在整圆墙与这种楼板上实际怎么表现（多半是在 `ORIENTATION`
求值上报错、停在那里）——**读代码推断**，没有 E3D。

### 1.3 任务 3：EM4 支架字高为 0、管道中心标识零长（核对过数据）

**61 个支架的根因不只是「没有型钢尺寸线」。** PML 的字高：`cheight = maxsctndis × cheightbili(0.2)`（`suiSupport.draw` L992）；
它是 0 时出图平面引擎取 `dirobject.maxlen / 20`（`planesystem.pmlobj` L153-159），`maxlen` 来自视向取点的跨度。这 61 个支架
（60 个在 `/1RX03-MSUP`：FRMW + 3 根没有 SPREF 的 SCTN + 两个同点的 ATTA；1 个暖通支架 `24381_71247`：只有 FRMW）的型钢建不成
构件，视向取点只剩管道点附件的点构件一个——这个取点是本库 `D-SUPP4-001` 修正之后才有的，PML 收不到管道附件。一个点的跨度是 0。
而 PML 在取点为空时本来就退到 2000 mm 管段的两端（`suilookdirections.getpossdirs` L189-202）。

修正（`D-SUPP4-033`，`plane_layout::look_points`）：取点撑不起跨度（三向都不超过 1 mm）、又有管段时改用管段取点。61 个支架的
「管道信息」字高成了 70.7 ~ 100（中位 90.6）。多个管道点撑得起跨度的支架不变。再没有管段时字高定不出来：尺寸与标签都不出，
报 Warning `support.cheight_undetermined`，不画零字高的文字（真实数据里没有遇到）。

**5 个零长的「管道中心标识」：外径读不到。** 两条线的半长是 `AOD / 2`（`getpipeELtextindexs` L1255-1267）。PML 取 `aod of atta`
（L1215），外径是 0 时两个端点重合，`mbdaidline` 建不出方向、返回 false，什么都不画；退到前后 TUBI 的写法（`getattaaod`，L1316）
在调用处被注释掉了（L1216）。本库原先下发两条零长的 `aid_line`，现在不发，留一条 Info `support.pipe_od_missing`。全库 398 个
支架是这样（几乎都在暖通 HVAC-SUPP 区，另 `/1RB06-MSUP` 6 个、`/1RX03-MSUP` 4 个），那 5 个在其中。

2556 个支架候选重算：56 个只是「管道信息」有了字高与位置；5 个另去掉零长中心标识、多一条 Info；393 个原先走通的支架少了
两条零长线、多一条 Info；其余 2102 个（1845 个归属对象）逐字段不变。

## 5. 需要用户拍板的

1. **`D-PIPE-046` 接不接受**（`f49c70f`）。它与 PML 字面不同，动了 28% 的安装角度（260 / 924），一条金样跟着重录。不接受就
   `git revert f49c70f`，别的修正不依赖它：代码、裁决、金样自动合并；`docs/MIGRATION.md` 与 `fixtures/golden/README.md` 会冲突
   （后一笔 `d31a989` 也在这两个文件末尾加了段落，用 `git merge-tree` 试过），冲突处留下 `d31a989` 的段落、去掉讲 `D-PIPE-046` 的
   那几段即可。回退之后仍有 145 个安装角度的弧半径不到 3 mm、角度字压在顶点上。
2. **首尾没设（在原点）的 BRAN 要不要不画端点标签**。现在照 PML 画在原点、另点名一条 Warning（8 条 BRAN）。不画的话要登记
   裁决，而且得宿主在视图里点明「原值是 0 0 0」才判得准。
3. **房间号的归属**。`D-CIVIL-017` 之后建筑 46 / 152、土建 47 / 135 个房间在任何一块板上都没有房间号。要补，得定规则（例如
   「标注点所在的板，没有就取平面上最近的那块」）并由宿主给每个房间指定归属板。
4. **读不到外径时要不要用通径画「管道中心标识」**。现在照 PML 不画（398 个支架，多是风管）。相关：电缆桥架的 `aod` 是 25
   （宿主查实取的是桥架规格的 `PARA[2]`，侧高），中心标识因此只有 25 mm 长，而通径是 100 ~ 500。
5. **没有型钢、只有管卡 / 多个管道点的支架要不要改成 PML 现行的取点**（一律用管段取点）。现在保持 `D-SUPP4-001` 的做法，只在
   取点撑不起跨度时才用管段。改的话纯管卡支架的字高从 50 变成 100 左右、定位尺寸换到水平面（试过，金样
   `support-em4-clamp-only` 会变，所以撤回了）。
6. **FLOOR 的竖面要不要一律照墙面写**。现在只修了法向与观察方向平行的情形；另 18 块法向 E / W 的竖板照 PML 字沿竖向读。
7. **空 BRAN 的 `data.empty_branch` 算不算 error**（6 条）。库里就是空的；现在是 Error，补了规则号。
8. **一个包里成百上千条 `civil.member_off_face` 要不要并成一条**（例：`24381_25804` 一个包 681 条；全库 6.9 万条 Info）。埋板是
   整框架一起收的（PML 相同），逐块点名现在很吵。
9. **字高要不要设下限**。最终输出里字高不到 1 mm 的图元 128 个（126 个在土建 / 建筑的构件上：构件与墙面只擦到一条缝，尺寸
   是 1 mm 上下，字跟着缩），1 ~ 2 mm 的 928 个（791 个是 em9_pipe 的坡度符号）。照 PML 的缩放（读代码判断）；页面上要凑得很近
   才看得见。
10. 宿主代理列的：没有截面规格的型钢（SPRE 是 Nulref，206 个支架靠它才有型钢尺寸）要不要按中心线标长度。
