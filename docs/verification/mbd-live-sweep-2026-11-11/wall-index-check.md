# 找墙、楼板收墙与房间没有因设计库缺空间索引而漏库（2026-11-12）

#108 的结论与核对表。数据来自服务端第一批的调查（[batch1-host2](batch1-host2.md) 的 EQUI-2 一行与表），这里单独成文，以后看到
`locate.no_wall` 时不用再怀疑是漏库。

**可靠程度**：「核对过数据」= 读样例库（MDB `/ALL` 的 29 个设计库，用一个临时探针从各库的 WORLD 整树走一遍，只读 `.dat`）逐个数的；
「读代码推断」= 读服务端源码得出、没有跑过。

## 问题

设备找定位墙、EM4 支架取参考视向、EM9 架装支架找墙，以及楼板找板旁的墙与房间，都是逐个设计库查空间索引表（SPAMAP）收候选；
某个设计库没有空间索引表时，这几路都直接跳过、不留话。离线最终标注包里有 523 台设备（EM4 151 台、EM9 372 台）在 50 m 内一面墙都
没找到（`locate.no_wall`）。要回答：这里面有没有一部分是「墙板所在的库整库没参与」。

## 结论：没有漏库，不用改代码

- 29 个设计库里有墙板（WALL / GWALL / STWALL / FLOOR）的 4 个——1112、6003、7009、7997，墙板分别 293、1、4、544 块——都有空间索引表，
  都参与找墙与楼板查询（核对过数据）。
- 没有空间索引表的 4 个库——7027、7334、7353、7741——墙板 0 块、房间面板 0 块（核对过数据）。
- 842 块墙板里 837 块在空间索引里有条目；没有条目的 5 块都没有几何，本来也参与不了（核对过数据）：

  | 墙板 | 类型 | 为什么没有条目 |
  |---|---|---|
  | `17496_106456` | GWALL | 没有几何（没有环，或环里没有顶点） |
  | `17496_117236` | GWALL | 同上 |
  | `24381_2162` | GWALL | 同上 |
  | `24381_25747` | FLOOR | 同上 |
  | `23393_4` | FLOOR | 同上（模板世界里的一块） |

- 房间面板 230 块（7997 库 229 块、8000 库 1 块）全有条目（核对过数据）。
- 设备找墙与 EM4 / EM9 支架找墙用的是同一个收候选的函数（`locate_candidates`），上面的结论对支架同样成立（读代码推断）。

所以 `locate.no_wall`「50 m 内一面墙都没找到」这条说明在样例库上是可信的。

## 没有核对的

- 「所钉会话」用的是离线端点的口径（各库最新会话）；联调后端的服务端按 MDB 钉会话，两者是否一致**没有核对**。
- 空间索引表里的条目是否都对得上元素当前的几何（条目会不会过时）没有逐条核对；这里只数了有没有条目。
