# MBD 尺寸标注全量联调扫描与后续修正（2026-11-11 起）

**结论**：2026-11-11 对共享联调后端上的全部 MBD 对象做了第一次全量核对——7059 个可标注候选（按归属对象去重 6802 个）逐个取数，
用前端的真代码走契约、映射、登记、排版。按归属对象数，当时 6410 个走通、**81 个在页面上整包失败或画不出**（契约拒收 67、映射拒收 7、
服务端 422 6、退化 1）、240 个回了没有图元的空包、71 个按规则不可标注。之后在求解器（plant-mbd）、服务端（gen-model）、前端（plant3d-web）
三层分批修正，每批都在全部候选上离线重放、过前端、逐对象比：从 11-12 的汇合起**失败的几类一直是 0、没有一个对象变差**。第四批之后
（求解器 `3dbf13a` + 服务端第四批）按归属对象是**走通 6490、空包 241、不可标注 71**；比第三批少的那一个走通是一块建筑楼板：它上面唯一的
房间号按 #125 只留在另一块板上，它没有可标的了，回带说明的空包。见下「结局」。

「走通」只是链路走通，不等于画得对。最终的标注包在真浏览器里按类抽样看过两轮（注入页面）：都装得进、画得出；查出的两类「画出来了但不对」
（局部 Z 轴朝下的墙整体高出一个墙高、原点在世界原点的设备复制件的定位尺寸从原点量起）已在第二批、第四批修正。PML 一行都没有在 E3D 里跑过。
**联调后端还没换版**，修正都在各仓库的本地分支上，没有合并、没有推送；合不合、什么时候换版由用户定（交接见 #127）。

跟踪：#103（MBD 全标注类型）下的子 issue #104 – #151。

## 口径

- **可标注候选**：沿模型树枚举出来、逐个请求的入口——BRAN、EQUI、支架（SUPPO 与 ZONE 直属的 STRU / REST）、WALL / GWALL / STWALL / FLOOR，
  共 7059 个。
- **归属对象**：答复里 `subject.refno` 指的对象，共 6802 个。ZONE 直属的 STRU 与配对的 REST 归到同一个支架（257 对，答复两两相同），
  候选里算两个、归属对象里算一个；没有标注包的答复（422）按候选自己算。
- **联调后端（11-11）**：2026-11-11 22:11 那一遍全量扫描（后端里的求解器是 plant-mbd `47eb83e`）。当晚它换过一次二进制，换完全量重扫，
  MBD 答复逐字节不变。
- **离线重放**：服务端的离线端点（`mbd_object_respond`，与 `GET /api/mbd/v2/object/{refno}` 同一个函数）在全部候选上出答复，再用扫描脚本过前端；
  汇合时在 6982 个标注包上与联调后端的答复逐个对过，离线这条路等于联调后端的端点。
- 各报告里的结论大多标着核对程度：「核对过数据」= 在整类对象上数过或逐个比过；「读代码推断」= 读源码得出、没有跑过。

## 初稿里写错、后来更正的

这份总览的初稿写于 11-11 22:35，下面这些后来查实是错的或没有依据：

- **可标注候选数当成了归属对象数**。初稿说「7059 个归属对象」，其实是候选：ZONE 直属的 STRU 与配对的 REST 各算一个、257 对答复两两相同；
  归属对象是 6802 个，EM4 支架 2207 个而不是 2391，仪表管支架 92 个而不是 165。扫描脚本现在两种口径并列。
- **D-PIPE-044 的原因**。初稿（与 `472a224`、`94bf16b` 的裁决）说是成员沿轴「相距小于 f32 的分辨率 / 只差千分之几毫米」。在真实输入上算下来，
  这 5 条直段的成员全在轴的横向上，沿轴跨度按精确算术是 0，是轴方向 1e-16 量级的残差算出了非零；`3b47289` 改了裁决。全库重算还看到另 4 条
  直段落在 0.5 mm 的阈值以内，它们的跨度是真的间距，同样按重合处理。
- **61 个支架「整个标注缩成一个点」**。是从一个样本推出来的：过了出口自检之后 56 个还有 25 mm 的管道中心标识，只有 5 个全部缩成一点（外径
  读不到，中心标识零长）。根因也不只在求解器，见下一条。
- **「服务端读不出这些 SCTN 的截面数据」**。不是读漏：被跳过的 1149 根 SCTN 里 1127 根的 SPRE 是空引用，22 根指向目录库里不存在的元素
  （[host-findings](host-findings.md) B）。
- **第 3、5、6 类「出处没查」**。后来查到：第 3 类是竖楼板，第 5 类是整圆弧墙的弦长，第 6 类是空支管——422 的说明文字本身也不对。
- **「关掉 LOD 也画不出来」的 21 个对象**（18 台设备、3 条管道），初稿说「可能是假象」：是假象。脚本摆相机时把离原点 1.5 以内的三元组当方向
  丢掉，而输入的单位是米，原点附近的真位置被丢了；同一个猜法还把没有归一化的读数方向（`labelAlong`，最长 70）当成点收进包围盒。扫描脚本
  改成按字段取点之后，同一批答复上这 21 个旧脚本全报、新脚本 0 个，结局没有一个对象变。「画得出来」也不等于「画得对」：这批设备复制件的
  定位尺寸后来查实是从世界原点量起的（N2，#121）。
- **「16 个模板站点没扫」**。后来扫了：12925 个候选，12874 个不可标注、51 个走通，没有新的失败（[coverage-inventory](coverage-inventory.md) 第 4 条）。
- **「新求解器没有在真实输入上跑过」「页面这一层没有跑」**。后来服务端导出了全部对象的真实输入，求解器在上面逐版重算；页面层在真浏览器里
  看了八种类型，又用最终标注包复查了两轮。
- 11-11 22 点复核时已经改掉的几处：安装角度半径初稿说是「回上一条坏带的外沿、PML 也画成点」，实测是一条两端都是残差的零宽带，改成源头不收

## 怎么扫、怎么重放、怎么比

```powershell
# 仓库根目录；只发 GET，不写库、不生成模型。用法与口径见各脚本的 --help
node scripts/mbd-live-sweep.mjs --save-payloads all --out .scratch/mbd-live-sweep/full        # 对联调后端全量扫，每个答复都存下来
node scripts/mbd-live-sweep.mjs --refnos 24381_71247,24383_75665,24383_97932,24381_2147,24381_25804   # 11-11 各类失败各一个
node scripts/mbd-live-sweep.mjs --mbd-base <修过的后端> --out .scratch/mbd-live-sweep/fixed      # MBD 换一个后端，模型树仍读缺省的
node scripts/mbd-live-sweep.mjs --payload-dir <离线端点的输出目录> --out .scratch/mbd-live-sweep/replay   # 重放，不连后端
node scripts/mbd-sweep-compare.mjs <基准目录> <当前目录> --out .scratch/mbd-sweep-compare/x    # 与一份基准逐对象比
```

- **扫描**（`scripts/mbd-live-sweep.mjs`）：沿模型树枚举候选（39 个 SITE 里扫 23 个，跳过 16 个 MDS / 模板站点）→ `GET /api/mbd/v2/object/{refno}`
  → 前端真代码 `parseMbdV2PipeData`（与页面同样的选项）→ `mbdV2ToExternalRecords`（有一条映射不出就整包拒绝，ADR 0046）→ `ExternalDimensionRegistry`
  → `layoutViewport` + `ThreeViewportProjector`，带 LOD、关掉 LOD 各排一遍；页面取数的两道护栏（15 秒、20 MB）另记一类。汇总两种口径并列；
  排版一节单列「带 LOD 一条都不画」「关掉 LOD 仍有记录画不出来」的候选——相机是脚本把整包标注装进一个视口摆的，不是页面的相机，这两张清单
  要到页面上对着看才算数。11-11 那一遍用时 85 秒，取数耗时 p50 / p90 / p99 / 最长 = 32 / 47 / 135 / 2883 ms。
- **重放**：`--payload-dir` 目录里的 `index.jsonl` 给每个答复的状态码（离线端点与扫描脚本 `--save-payloads` 都写它），422 的错误信封照 422 走；
  没有它时都当 200（11-11 那一版脚本存答复时不写它，重放那时存下的目录要先按当时的 `results.jsonl` 补一份）。
- **比对**（`scripts/mbd-sweep-compare.mjs`）：两边各给一个标注包目录或扫描输出目录；标注包剪掉 `meta.source_version` 与 `input_refno`，
  数值按 f32 比、键序无关，图元与诊断去掉 id 按内容配对。每个候选归到「结局变了 / 图元变了 / 别的字段变了 / 只有诊断变了 / 只有扫描指标变了 /
  只有 id 平移 / 只有顺序变了 / 相同」，只换了 id（例如滤掉几个房间号后后面的序号前移）、只换了顺序的不算内容变化；字面不同、按 f32 相同的
  单列个数。两种口径各出结局分布与变化矩阵（归属对象取候选里最差的结局，与扫描脚本的汇总同一个定义），并列扫描指标（结局、reason、
  httpStatus、记录数、图元数、契约诊断、error 条数、关掉 LOD 画出 / 画不出 / 非有限数）、带 LOD 画出的条数变了的对象、诊断按规则号的增减，
  每个变了的候选写出每处的改前 / 改后。只比标注包时结局只看状态码与有没有图元，要按过前端的结局比就给两边配上扫描结果
  （`--baseline-results` / `--current-results`）。
- 页面右键入口还收 NOZZ / HANG / FRMW / SCTN / PANE / PCLA，服务端把它们归到上面那些对象，脚本不逐个当入口扫；抽了 113 个直接请求，都回 200
  并归到了所属的设备 / 支架上。
